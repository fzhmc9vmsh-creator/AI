# 前提の事前登録(R2-3、2026-10-12 記録)

> 記録の時点: 本表は model3.py を走らせる前に固定した。以後の変更は §9 の変更履歴に、変更前の値・理由・
> 変更が計算結果を見た後かを残す。
> **株価の既知性(正直な申告):** 分析者は第1回の分析で株価(2026-10-09 $141.40)を見ている。完全な
> ブラインドではない。対策として、各前提は (1) 市場の外部データ(国債利回り・社債スプレッド・格付実績)、
> (2) 会社開示とガイダンス、(3) 調査で得た事業の単位経済、のいずれかから機械的に決め、株価・時価総額・
> 予想PER(株価から逆算した値)は一切使わない。株価との比較は最終章(Phase 6)でのみ行う。

## 1. 評価の方法(なぜこの方法か)

| 項目 | 選択 | 理由 |
|---|---|---|
| 枠組み | 事業別 DCF の合算(SOTP)+ 負債の節税効果(APV)− 負債等 → 倒産確率で加重 | 事業ごとに成長・利益率・資本集約度・リスクが全く違う(保守は年金型、AI インフラは設備型)。全社に1つの PER や WACC を当てると、資本集約度と倒産リスクを二重に数えやすい(第1回の失敗) |
| 割引率 | 事業別の「負債なしの資本コスト」= 無リスク金利 + 資産ベータ × 株式リスクプレミアム | レバレッジが年ごとに大きく変わるため、目標資本構成を置く WACC より APV が適する。倒産リスクは割引率に入れない(§6 で1回だけ数える) |
| ターミナル | 値 = 翌年 NOPAT ×(1 − g ÷ ROIC)÷(r − g)。事業別 | スキル §5。成熟後の PER を「日本平均」ではなく、成長率と ROIC から決める |
| SBC | 費用として利益率に含める(事業実態の利益)。株数は現在の希薄化後株数で固定 | 希薄化と SBC 費用の二重計上を避ける |

## 4. マルチクラウド DB と AI Database の事業価値(F22)の式と前提

売上_t = DB 保守の母数 × 他社クラウドに置かれる比率 × 採用率_t × 移行後の売上倍率 ×(1 + 利用量の伸び)^年数

| 前提 | ベース | 強気 | 弱気 | 根拠 |
|---|---|---|---|---|
| DB 保守の母数 | 11.0 | 11.0 | 11.0 | ライセンス・サポート全体 約 $19.5B(R4 算出)のうち DB を 55〜60% と推定(推定。出典なし) |
| 他社クラウドに置かれる比率 | 50% | 60% | 40% | AWS・Azure・Google の IaaS シェア計 63%(Synergy)。オンプレに残る分を引いた判断 |
| FY36 の採用率 | 35% | 55% | 15% | 現在の採用率 約 6%(年換算売上 約 0.8B から逆算: 0.8 ÷(11 × 0.5 × 2.5))。S 字で FY30 に 24% |
| 移行後の売上倍率(保守 1 に対し) | 2.5 倍 | 3.5 倍 | 1.8 倍 | 会社・アナリストの数値は見つからず(R4 欠損)。ECPU 課金はインフラ分を含むので 1 倍を大きく超える。仮定として明示 |
| 利用量の伸び(移行済み分) | 年 6% | 年 10%(26ai の AI 利用を含む) | 年 3% | 消費課金は顧客のデータ量に連動して自動で増える |
| 共食い | 保守売上の喪失 = 母数 × 比率 × 採用率。価値は利益率 75% で計算 | 同 | 同 | 評価の合計ではソフト保守の −3%/年に含まれる。F22 の「純増の価値」を示すときだけ差し引く |
| 現在の年換算売上 | 約 0.8(0.4〜1.5) | | | クラウド DB 全体 約 $2.8B(Q1 FY26、+32%)と、マルチクラウド +353% から連立して逆算(推定) |

**AI Database(26ai)** は追加料金なしで、単独の売上が無い(R4)。したがって独立の行にせず、採用率と利用量の伸びを通じて効く要因として、強気と弱気の幅に含める。

## 6. 倒産確率(F21)の数え方: 1か所で1回だけ

| 項目 | 選択 |
|---|---|
| 価値への反映 | 確率加重: 株主価値 =(1 − FY36 までの累積倒産確率)× 存続時の株主価値。倒産時の株主回収は 0 |
| 倒産確率の種類 | **実際の倒産確率(格付の過去実績)をベースに使う**。CDS から逆算した値はリスクプレミアムを含む(リスク中立)ので、割引率のリスクプレミアムと二重になる。ストレスの参考としてのみ示す |
| 格付の経路の決め方 | 総債務 ÷ EBITDA と FCF の符号から機械的に決める: FCF<0 かつ倍率>4.5 が2年続く、または FY29 に FCF≤0 → BB+(S&P のトリガー)。倍率>5.5 → BB。FCF>0 かつ倍率≤3.5 → BBB。≤2.5 → BBB+。それ以外 → BBB- |
| 格付別の年間倒産確率 | BBB+ 0.15%、BBB 0.27%、BBB- 0.55%、BB+ 0.90%、BB 1.2%、B 3.3% | S&P 1981〜2024 の区分平均: BBB 5年 1.36%、BB 5年 5.75%、B 5年 15.6%(R5)を年率にした値。BBB-・BB+・BBB+ はノッチ別データが欠損のため補間(仮定) |
| FY36 以降 | 正常な資本構成に戻り、通常の倒産リスクは資本コストに含まれるとみなす(加重しない) |
| 顧客集中(OpenAI) | シナリオ(弱気)でのみ数える。資本コストに上乗せしない |
| 資本集約度 | 各年の capex と更新投資(DCF)でのみ数える。倍率の割引はしない |
| 希薄化 | SBC を費用に含め、株数は固定。倍率の割引はしない |

## 7. 較正(株価ではなく会社の実績に合わせる)

- ソフト保守の利益率 = Q1 FY27 の全社営業利益(GAAP 6.728 + 買収無形償却 0.202 + リストラ等 0.094 = 7.024B、SBC は費用のまま)から、他の事業の営業利益を引いた残差 ÷ ソフト売上 5.55B。
- 検証: FY27 の売上がガイダンス(≥$90B)に近いこと、FY27 の総債務 ÷ EBITDA が S&P の見込み(約 4.4 倍)と矛盾しないこと、FCF の黒字化年度をアナリスト(FY29)と並べること。**株価・予想PERでは検証しない。**

## 8. シナリオと確率

| シナリオ | 確率 | 内容 |
|---|---|---|
| ベース | 55% | §3〜§5 |
| 強気 | 20% | 容量 FY31 に 15GW・FY32 以降 16GW、単価 FY30 以降 11.0、マルチクラウド採用 55%・倍率 3.5・利用量 +10%、SaaS +1pt、OCI 一般 +2pt |
| 弱気 | 25% | OpenAI の支払いが FY29 から半減。課金容量 FY29 7.0・FY30 以降 7.5(他顧客への再販で FY33 以降 年 +0.5GW)。リース(約 12GW 分)は解約できず、遊休分の賃料 1.5B/GW・年が残る。単価 FY29 以降 8.0。新規投資は課金容量分のみ。マルチクラウド採用 15%・倍率 1.8、ソフト保守 −5%/年、SaaS −2pt |

弱気の確率を強気より高くしたのは、損失側の裾が厚い(解約できないリース、OpenAI の資金調達への依存、CDS 227bp)ため。
