# audit-loop.md — 3 層監査・差し戻し・完成宣言

代替版(2026-10-17)。原本は同期フォルダに無いため、invest-consulting-deck の scripts/(lib.js・audit_deck.py)と deck-rules-v2.md から再構成した。

順序は L1 構造 → L2 仕様(機械)→ L3 視覚。指摘は Blocker / Major / Minor に分け、Blocker と Major が 0 になるまで直す。最大 3 周。3 周で解消しないものは既知の制約として納品時に報告する。自己申告は認めない。完了は下記のログで判定する。

## 1. L1 構造(人が読む)

meta.js の title・theme・why の列と、各スライドの本文を読んで確かめる。

- [ ] メッセージの通し読み: title だけを順に読んで話が通じる(message-storyline.md §5)
- [ ] 縦の論理: 本文がタイトルを証明している。無関係な要素がない。章のタイトル群が章の「なぜ」に答える
- [ ] 横の論理: 同じ階層の柱が同種で、重複と漏れがない
- [ ] 見出し帯: 全スライドにテーマ札と「なぜ見るか」がある。現在地と (k/n) が正しい。「なぜ」は 1 行・全角 60 字以内で、判断の材料を述べている
- [ ] タイトル: 完全文、体言止めなし、2 行まで、改行が意味の切れ目
- [ ] 薄いスライドがない。数値 3 個以上は図になっている。図表ゼロのスライドがない
- [ ] 出所がある(機械監査は出所の欠落を報告しない。ここで人が見る)
- [ ] 総括と本編の数値が一致している。中扉の節とページ範囲が実際と合う
- [ ] 条件スライド: 評価バッジ、根拠、評価の理由、C 以下は監視 KPI の帯

## 2. L2 仕様(機械監査)

実行する。

```
node one.js 17           # 1 枚。図の重なり件数・監査結果・画像のパスを表示
node build.js            # 全体 → ORCL_deck.pptx。重なり件数を表示
python3 audit_deck.py ORCL_deck.pptx --json audit.json | tee audit_L2.log
```

### 検査項目(audit_deck.py)

| 項目 | 判定 | 重大度 |
|---|---|---|
| bounds | 範囲外(x・y < −0.01、右端 > 13.343、下端 > 7.51) | Blocker |
| margin | 左 x < 0.25、右端 > 13.083、上 y < 0.25(`hdr_` は 0.04)、下端 > 7.3。`bg_` は除外 | Major |
| palette | スライド XML に 14 色以外の srgbClr(design-system.md §1) | Major |
| font-size | 文字の明示サイズが 8pt 未満 | Major |
| font-name | Meiryo UI・Arial 以外 | Minor |
| title-size | `title` の最大サイズが 18〜20pt の外 | Major |
| text-fit | 推定の高さ > 枠 + 0.02 | Major。枠の 1.25 倍超は Blocker |
| title-wrap | `title` の段落が 1 行に収まらない / 3 段落以上 | Major |
| orphan | 折り返した段落の末行が全角約 2 字以下 | takeaway・kicker・hdr_why・tile* は Major、他は Minor |
| num-split | 行末が数字で次行頭が単位(ドル・億・%・年 など) | Minor |
| overlap | 文字枠どうしが 0.03in 超重なる(`ovl_`・`bg_` は除外) | Major |
| footer | 内容スライド(2 枚目以降)にページ番号がない | Major |
| title-form | `title` が 18 字未満 / 句点で終わる | Major / Minor |

- 推定式は blueprints.md §4。LibreOffice の代替フォント幅に 8% の余裕を見ている。
- 表とチャート(文字枠を持たない shape)は、文字の収まり・フォント・重なりが検査されない。palette は表のセルまで見るが、チャート内の色は見ない。L3 で目視する。
- ブループリントの座標との一致、チャートの比例、見出し帯の有無、出所の有無は機械監査にない。L1・L3 で見る。

### 合格条件

1. `audit_deck.py` の結果が `RESULT: PASS`(Blocker 0 かつ Major 0)
2. **flowMap の重なり検出が 0 件**。`one.js`・`build.js` が「図の重なり 0 件」と表示する。検出するのは次の 10 種: ラベル × 箱 / ラベル × 札 / ラベル × 囲みの名前 / ラベル × ラベル / ラベルが図の領域の外 / ラベルが別の線を隠す / 札 × 箱 / 囲みの名前 × 箱 / 箱 × 箱 / 線が無関係の箱を横切る。1 件でも出たら不合格(Major 相当)
3. Minor は残してよい。ただし画像で実際に起きていれば直す(deck-rules-v2 §4)

## 3. L3 視覚(全ページを目で見る)

画像にする(`one.js` と同じ変換)。

```
soffice --headless --convert-to pdf ORCL_deck.pptx
pdftoppm -jpeg -r 80 ORCL_deck.pdf pg      # pg-01.jpg …
```

レンダリングせずに完成と言わない。手段がない環境では、その旨と代わりの検証を報告する。全ページを開き、次を見る。

- [ ] 文字の切れ・はみ出し(箱、表のセル、タイトル 2 行)
- [ ] 改行の位置(意味の切れ目、末行 1〜2 字、数字と単位の泣き別れ)
- [ ] 重なり(線上のラベル、札、バッジとタイトル、囲みの名前)
- [ ] 線は直角か。矢頭が箱に届くか。線が文字を横切っていないか。種類が凡例どおりか(カネ / モノ / リスク / 契約)
- [ ] 色が意味どおりか(赤はリスクとマイナスだけ、評価バッジの色、装飾色なし)
- [ ] 見出し帯(今の章だけ緑、テーマ札、なぜ)
- [ ] 余白と整列(左端 0.5、右端 12.83、本文の下端 6.75、出所 6.88)
- [ ] 図が値に比例して見えるか。ゼロ線、単位・期間・出所、予測の区別
- [ ] 密度: 空白が大きすぎない。詰めすぎて 8pt 未満に見えない
- [ ] 同種の図が同じ座標・同じ見た目か。ページ順
- [ ] 代替フォントの幅違い: 疑わしい箇所は文字を削る

重大度(L1・L3 は代替版の運用): 文字が読めない・図が壊れている・数値の誤りは Blocker。重なり、文字切れ、体言止め、見出し帯の欠落、薄いスライド、数値に図がない、は Major。整列のずれ、末行 1〜2 字は Minor。

## 4. 差し戻しの手順

1. 指摘を層(L1/L2/L3)と重大度で記録する(スライド番号、現象、原因)。
2. 原因を切り分ける: 設計書(meta.js・指示書)/ 部品の引数 / 内容の不足。
3. **設計書から直す**。pptx だけの場当たり修正をしない。座標を動かして収めず、文字を削る。
4. 該当 1 枚を `node one.js NN` で再実行(重なり 0・PASS・画像を目視)。
5. `node build.js` → `audit_deck.py` → 全ページを再び目視。周回を数える(最大 3)。
6. ユーザーからの指摘も同じ手順で、該当スライドの設計書から直す。

## 5. 完成宣言の条件

次がすべてそろったときだけ「完成」と言う。ログのない「確認しました」は虚偽報告とみなす。

1. `audit_L2.log` に `RESULT: PASS`(Blocker 0・Major 0)
2. `build.js` の出力に「図の重なり 0 件」(`build.log`)
3. 全ページの画像を見た記録(日付、枚数、見たページ、直した箇所)
4. L1 のチェックリストを通した記録
5. 画像で実害のある Minor が残っていない

納品物: pptx / スライド設計書(meta.js と指示書)/ 監査ログ(audit_L2.log・build.log・周回ごとの検出と修正の履歴)/ 未解消の既知の制約 / データの出所一覧。
