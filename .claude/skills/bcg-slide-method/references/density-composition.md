## 1. 密度基準

1. **1 枚で議論が完結する**: タイトルの主張を、同じスライドの数値・出所だけで証明できる。他のページを見ないと意味が通らないなら不足。
2. **数値 3 個以上は比例描画のチャート**にする(§2)。
3. **薄いスライドは作らない。統合する**。利用者の指摘: 「20 ページとかホントにいる？総括で良くない？」
   - 前提条件だけの条件、タイル 3 枚だけ、箇条書き 3 行だけのスライドは、評価一覧・総括・中扉の注記に統合する。
   - 構造が単純すぎて関係図にならない条件(例: 上場市場)は、チャート + 右パネルか KPI タイルに替える。ただし 1 枚 1 条件の原則は保つ。
4. **本編の分析スライドは複合構成**にする(§3)。単一の部品だけの本文は、証拠が 1 種類しかない印象になる。
5. 全図表に単位・期間・出所を付ける。出所のない数値は載せない。

上限側: 8pt 未満の文字は禁止(機械監査 Major)。文字が入らないときは座標や縮小で収めず、文字を削るか 2 枚に分ける。

## 2. 視覚エンコーディングの義務

- 数値 3 個以上の比較・構成・推移は、長さ・位置が値に比例する図(`chartPanel`、`s.addChart`、`timeBand`)で描く。
- 数字をテキストボックスに並べただけの「チャート風」は差し戻し。
- `kpiTiles` は別々の指標の提示に限る。同じ指標の比較・推移はタイルに並べず図にする(この区別は代替版の運用)。
- 期間の長さを比べるときは `timeBand` で長さを並べる(契約・リース・償却・優位の期間)。
- 正負が混ざる棒はゼロ線を引き、負を赤(C0392B)にする。予測は薄色か枠線のみで、予測である旨を注記する。系列は 4 本まで。

原本の C-1〜C-5 の定義は手元にない。上は ORCL 版で実際に使った型から整理したもの。

関係図(C-4)の基準は deck-rules-v2 §3:
- 配置: レーンで領域を分け、左から右へお金・モノの順。行をまたぐ線は直角に折る。
- 粒度: 自社を 1 箱にしない。事業・資産・機能に分けて自社 3〜5、外部 3〜5、合計 10〜14 箱。
- 深さ: 矢印と箱の副題に数量(金額・率・期間)。リスクの所在を赤枠・札で示す。右に「何が起き、なぜ評価に効くか」を 1 項目 2 行で書く。
- 評価の境界: 右パネルの下に「上がる条件」「下がる条件」。評価 C 以下は監視 KPI の帯。

## 4. 事業・条件スライドの標準の厚み

- 事業理解は 3 枚(積み木 + 5W1H + 用語の注釈 / 事業どうしの関係図 / 注目度の高い成長分野)。
- 会社のシナリオは 2 枚(ストーリー図 / 部品の採点と会社目標・コンセンサス・自前推計の差)。
- 条件 5(経営者)は経歴から評価し、「経歴 → 現職 → 担う事業 → 結果」の関係図にする。

## 5. データ → 切り口の設計

生データ(Excel・決算数値)を 1 つの見方だけで主張にしない。

1. 標準の切り口で複数の集計を作る(代替版での整理)。
   - 時間: 推移・前年比・年平均成長率
   - 構成: セグメント別・顧客別・地域別の比率
   - 分解: 価格 × 数量、増収の源泉ごとの寄与
   - 比較: 対同業・対計画・対コンセンサス
   - 集中: 上位への偏り、ばらつき
   - 感応度: 前提が上下したときの結論の動き
   - シナリオ: 強気・ベース・弱気
2. 切り口ごとに「だから何か」を 1 文で書く。
3. 最も強い主張を採用し、他は根拠にするか捨てる。採用理由を設計書に 1 行残す。

## 6. 密度検算(設計書の記入欄)

各スライドで数える: 情報単位数(図・表・パネルの個数)、数値の個数、うち図になっている数値、出所の有無、階層(主張 → 根拠 → 出所)。

薄すぎ警報: 図表ゼロ / 数値 3 個以上なのに図がない / 出所なし / 全スライドの中で情報単位・数値が突出して少ない。該当したら実装に進まず、掘り増すか統合する。
