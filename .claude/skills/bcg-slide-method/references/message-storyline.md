# message-storyline.md — 文章からストーリーラインとスライド設計書まで

代替版(2026-10-17)。原本は同期フォルダに無いため、invest-consulting-deck の scripts/(lib.js・audit_deck.py)と deck-rules-v2.md から再構成した。

流れ: 文章 → 主張と根拠の抽出 → ピラミッド → 章立て → 1 スライド 1 メッセージ → 見出し帯(テーマ・なぜ)→ 通し読み → 設計書。図を描くのは設計書の承認後。

## 1. 主張と根拠の抽出

段落ごとに「主張 1 文 + 根拠(数値・事実・出所)」を 1 対で抜き、台帳にする。

| ID | 主張(完全文) | 根拠(数値+単位+期間) | 出所 |
|---|---|---|---|
| a1 | DB の保守料が営業利益の柱である | 保守はライセンスの年 22% | 10-Q |

- 主張は述語のある文にする。「DB の概況」のような名詞句は主張ではない。
- 根拠のない主張、出所のない数値は台帳に入れない。出所は図表ごとに後で必ず書く。
- 数値は基準を揃える(GAAP と非 GAAP、年度と暦年を混ぜない)。基準は根拠欄に書く。
- 入力が報告書(meigara-bunseki-method 等)なら、内容は報告書が正。スライド化で新しい主張を足さない。

## 2. ピラミッドと章立て

- 最上位は結論 1 文。その下に柱 3〜5 本、各柱の下に根拠。
- 縦の論理: 上から「なぜそう言えるか(Why so?)」、下から「だから何か(So what?)」が成り立つこと。
- 横の論理: 同じ階層の柱は同種(要因・時系列・構成のどれか 1 種)で、重複と漏れがない。
- 柱を章にする。章は 4 前後。先頭に結論(エグゼクティブサマリ)を置き、以降の章で根拠を確かめる順にする。
- 章ごとに「章のなぜ」を 1〜2 行で書く。中扉(agenda)に載り、節とページ範囲の一覧が並ぶ。単独で 1 枚にしない項目(前提条件など)は中扉の注記か総括に入れる。
- 枚数の目安: 持ち時間 5 分で 5〜7 枚、30 分で 15〜25 枚(SKILL.md Phase 0)。

## 3. 1 スライド 1 メッセージ

- タイトル = そのスライドの主張を述べた完全文(主語・述語・数値・So what)。体言止めは禁止。
- 2 行まで。各行は全角 38 字相当(19pt で 11.13in)に収め、意味の切れ目に "\n" を入れる。
- 機械監査: 18 字未満は Major、句点終わりは Minor、折り返しと 3 行以上は Major。

悪い例: 「事業理解」「収益構造の概要」
良い例: 「Oracle は DB を土台に、業務アプリ・クラウド・AI 容量を重ねて売る。\n利益は DB 保守、成長は AI 容量が担う」

- 本文はタイトルの証明に使う要素だけで組む。無関係な要素は 1 つも置かない。
- 数字の見せ方: 単位・期間・比較対象を必ず付ける。数値 3 個以上の比較・推移・構成は図にする(density-composition.md §2)。総括に書く数値は本編と完全に一致させる。予測は実績と区別して注記する。

## 4. 見出し帯(テーマとなぜ)は設計の段階で決める

利用者の指摘: 「なぜその説明や解説があるか分からない」。実装で後付けせず、設計書の段階で全スライド分を決める。

| 項目 | 役割 | 決め方 |
|---|---|---|
| テーマ | このスライドが資料全体で担う論点(札) | 名詞句。例: 結論 / 事業理解 / 競争優位 / 市場との差分 / リスク。条件スライドは「競争優位の持続(条件1)」の形 |
| なぜ見るか | 何を判断するための材料か | 1 行・全角 60 字以内。「この 1 枚が無いと何を判断できないか」に答える |
| タイトル | 結論(主張) | §3 |

- 「なぜ」が書けないスライドは不要か、他へ統合する。
- テーマ・なぜ・タイトルは同じ文にしない。タイトルは結論、なぜは見る理由、テーマは論点名。
- 章・節・テーマ・なぜ・タイトル・順番は meta.js に 1 か所で集める。ページ番号は順番から自動で付く。スライドのファイルにはタイトルとページ番号を書かない。
- 同じ節が複数枚なら現在地に (k/n) が付く。

## 5. 通し読みテスト

meta.js の title だけを順に読み、それだけで話が通じることを確かめる。次に「なぜ」の列を読み、章の「なぜ」につながることを確かめる。通らなければ図を描く前に並びと主張を直す。

## 6. スライド設計書の書式

1 枚ごとに次を書く。全枚数ぶんをユーザーに見せ、承認を得てから実装する。

```
## S{番号}  id: s08b
- 章/節:    第2章 2-1 事業理解(2/3)
- テーマ:    事業理解
- なぜ見るか: (1 行・全角 60 字以内)
- タイトル:  (完全文・2 行まで・"\n" で改行位置)
- リード:    (1 行・何をどう読むか。左右の役割、①〜 の凡例)
- 本文の型:  部品名 + 複合構成 + 選んだ理由(pattern-library.md)
- 本文の中身: 領域ごとの要素(箱・列・行・系列)と数値。関係図は箱・矢印・仕組み・理由・上がる/下がる条件まで
- 出所:     (資料名・版・日付。「出所: 」は部品が付ける)
- 密度検算:  情報単位数 / 数値個数 / 図になっている数値 / 薄すぎ警報の有無
```

原本の「スロット上限」は手元にない。代替として、文字数は blueprints.md §4 の式で枠ごとに検算する。
