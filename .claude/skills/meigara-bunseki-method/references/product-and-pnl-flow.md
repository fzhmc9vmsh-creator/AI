# 製品・損益フロー・競争優位の解剖(product-and-pnl-flow.md)【2026-10-12 新設】

> 新設の理由: Oracle の分析で、事業を「エンジン」の粒度でしか見ず、製品・サービスを
> 5W1H で棚卸ししなかった。損益を項目ごとの流れ(売上 → 原価 → 粗利 → 営業費の内訳 →
> 営業利益 → 営業外 → 税 → 純利益)で見なかった。競合に対する優位を、品質と価格の比較と、
> それを支えるバリューチェーンで説明しなかった。戦略施策(例: Oracle Database@AWS/Azure/Google)
> の事業価値を個別に試算しなかった。本ファイルはこの4点を Phase 1.5〜2.7 の必須工程にする。

## §1 製品・サービスの 5W1H 台帳(L0。事業本体10層の前に置く)

**目的:** 何を・誰に・なぜ・どう売っているかを製品単位で把握する。エンジン(原子単位)は
この台帳を束ねたものであり、台帳なしにエンジン式を書かない。

**対象:** 売上の 5% 以上を占める製品・サービスと、経営陣シナリオのピースになっている製品
(規模が小さくても対象。例: マルチクラウド DB、AI Database)。

| 列 | 書くこと | 失敗例 |
|---|---|---|
| Who | 顧客層(業種・規模・地域)と代表的な顧客名、意思決定者(CIO・CFO・開発者) | 「企業向け」で止める |
| What | 何を提供するか(機能・性能・付随サービス) | 製品名の列挙 |
| When | 契約形態と期間、利用のタイミング(常時・繁忙期・移行時)、更新の時期 | 書かない |
| Where | 提供場所(自社クラウド・顧客 DC・他社クラウド内・オンプレ)、地域 | 書かない |
| Why | 顧客が片付けたい仕事、代替手段とその費用・時間・リスク、乗り換えの難しさ | 「便利だから」 |
| How | 課金方式(従量・確約・サブスク・ライセンス+保守・成果報酬)、課金単位、販売経路(直販・マーケットプレイス・パートナー) | 書かない |
| How much | 公表価格・単価・値上げ履歴、売上規模・成長率・粗利率(開示または推定) | 数字がない |
| 競合と代替 | 主な競合3社と、顧客がそれを選ぶ条件 | 競合名だけ |

**合格基準:** 台帳の売上合計が報告売上の 90% 以上を説明する。各製品に How much の数字が
1つ以上ある。台帳から「顧客の成長に課金が自動で乗る製品」と「乗らない製品」を分けられる。

## §2 損益フロー図(F19、サンキー図)

**目的:** 1四半期(または1年)の損益を、セグメント別売上から純利益まで1枚の流れで示し、
各段の前年比で「どこで増え、どこで漏れているか」を一目で分かるようにする。

**必要情報要素(すべて前年同期比つき):**
1. 売上の内訳(セグメント別、または製品群別。地域別しかなければ地域別)と構成比
2. 売上原価(内訳が開示されていればライン別)
3. 粗利と粗利率
4. 営業費の内訳(販売・マーケティング、研究開発、一般管理、償却、リストラ等)
5. 営業利益と営業利益率
6. 営業外(支払利息、受取利息、その他の損益)。一時要因は別の枝にする
7. 法人税
8. 純利益
9. 非GAAP との差(SBC、買収無形資産の償却)。図の外に注記してよい

**描き方:** 左から右へ「セグメント → 総売上 → 粗利 / 原価 → 営業利益 / 営業費(内訳)→
純利益 / 税・利息」と流す。利益の流れは緑、費用は赤、売上は灰。各ノードに金額と前年比を
付ける。原価や営業費の前年比が売上の前年比を上回る箇所(マージンの漏れ)を強調する。

**読み方(図の下に必ず書く):**
- 増収率と、各費用の増加率の差(どの費用が売上より速く伸びているか)
- 限界利益率(増収のうち何%が営業増益に落ちたか)
- 営業外の比率(純利益のうち、本業以外から来た部分)。一時要因を除いた純利益

## §3 競争優位の品質×価格×バリューチェーン分析(F20)

**目的:** 「優位がある」と書く前に、品質と価格の両方で競合と比べ、その差を生む活動を
バリューチェーン(調達・設計・製造/建設・運用・販売・資金調達)の上で特定する。

**手順:**
1. **価格の比較:** 主要製品ごとに、競合3社の公表価格・実勢価格と並べる(単位を揃える。
   例: GPU 時間単価、vCPU 時間単価、データ転送 1GB、ライセンスのコア換算)。
2. **品質の比較:** 顧客が重視する品質指標で並べる(性能ベンチマーク、規模の上限、稼働率・
   障害実績、機能、サポート、第三者評価(Gartner 等)、市場シェアの推移)。
3. **位置づけ:** 「安くて良い / 高くて良い / 安くて並 / 高くて並」のどこにいるか。
   「安くて良い」なら、それが持続する理由が要る(競合が真似すると何を失うか)。
4. **バリューチェーンで説明:** 価格差・品質差を生む活動を特定し、各活動に証拠(数字)を
   付ける。例: 資本コスト(社債利回りの差)、設備の調達・建設の方式(リース・顧客持込)、
   設計(自社設計のハード・ネットワーク)、運用の自動化、販売経路(他社クラウド内での販売)。
5. **持続性:** その活動を競合が再現する費用と年数。再現すると競合が失うもの
   (カウンターポジショニング)。

| 製品 | 価格(自社 vs 競合) | 品質(自社 vs 競合) | 位置 | 差を生む活動(バリューチェーン) | 証拠 | 再現の費用・年数 |
|---|---|---|---|---|---|---|

## §4 戦略施策(シナリオのピース)の事業価値の試算(F22)

**目的:** 経営陣シナリオのピースを、まだ小さくても1株当たり価値で試算する。「まだ小さい」
「成長率は高いが絶対額が不明」で止めない。

**式(基本形):**
価値 = 対象顧客数 × 採用率(年次の経路)× 顧客あたり増分売上 × 増分利益率 × 持続年数の価値
     − 既存事業の共食い(移行で失う売上 × その利益率)− 追加投資

- 採用率は S 字(導入・普及・飽和)で置き、現在値を開示(成長率・顧客数の伸び)から逆算する。
- 顧客あたり増分売上は、会社の説明(移行で売上が何倍になるか)、価格表、事例から置く。
- 共食いを必ず引く(例: オンプレ DB の保守売上が、クラウド DB に置き換わる分)。
- 結果は SOTP の1行として載せ、強気・ベース・弱気の幅と、確認 KPI(顧客数・リージョン数・
  売上の開示)を付ける。
