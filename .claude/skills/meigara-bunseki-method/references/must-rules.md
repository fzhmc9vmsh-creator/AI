# 必ず守る規則(利用者の指摘から作った一覧)

どれも実際の分析で起き、利用者に指摘された誤り。規則ごとに「誤りの例」「正しいやり方」「どこで止まるか」を書く。
「どこで止まるか」が検査(scripts)の規則は、検査を通せば守られる。「自分で確かめる」の規則は、各工程の終わりに
この表を上から読んで確かめる。

## A. 計算と価値評価(valuate.py が守る。手で計算しない)

| # | 規則 | 誤りの例 | 正しいやり方 | どこで止まるか |
|---|---|---|---|---|
| A1 | 構造評価が変われば、許容 PEG と α は必ず変わる | C が 3 → 0 に減り条件6 が A に上がったのに、等級が B のままなので PEG を据え置いた | 等級の中の位置を条件の点数(S5〜E0 の平均)で決める | valuate.py(grade_of) |
| A2 | 妥当 PER は「許容 PEG × g」だけで決める | 同業の PER・PEG × g・DCF の倍率を平均し、実質の PEG が 0.5 前後になった | 同業の PER・DCF・TBV×ROTCE は交差確認として並べるだけ | valuate.py / gate valuation |
| A3 | g は当該年度から 3 年の EPS CAGR | 翌年度から 3 年(減速の後)を使い、成長を小さく見た | 年度 t の g は t → t+3。g が 50% を超えたら上限と併記 | valuate.py |
| A4 | 「PEG 1.0 × g」の値を必ず併記して検算する | EPS が年 30〜40% 伸びるのに、理論株価が PEG 1.0 の値より低かった | 許容 PEG > 1 で PEG 1.0 の値を下回れば計算の誤り | valuate.py(検査 NG) |
| A5 | 比べる期間を揃える | 2026→29 年の伸びを、2025→28 年の中期目標と比べた | cagr_windows で目標と同じ期間の CAGR を出して比べる | 自分で確かめる |
| A6 | 数字は 1 回だけ丸める | 23.846 を 23.85 にし、さらに 23.9 にした | valuation.json の display(表示値)を写す | lint_deck.py / gate report |
| A7 | シナリオ確率は証拠から出す | 固定の 25/50/25 を置いた | 節点ツリー(tree)か証拠つきの scenarios。強気と弱気を同じ粒度で | gate valuation |
| A8 | リスクは 1 か所で 1 回だけ数える | 信用の不安を倍率でも確率でも割り引いた | 信用・資本・希薄化は EPS 経路・確率・株数で数え、倍率で割り引かない | 自分で確かめる |
| A9 | 前提は株価を見る前に固定する(事前登録) | 株価に合わせて PEG を動かした | 資本コスト・EPS 経路・シナリオ確率を書いてから prices を入れる。後で変えたら理由を残す。例外は条件6・7(市場との比較の条件)で、前提を固定した後に株価で採点する(前提は動かさない) | 自分で確かめる |
| A10 | 証拠なしに評価を下げない(上げもしない) | 根拠が揃わない条件を C にし、C が 4 つになって総合が C に落ちた | 2 周調べても決まらなければ「保留」(確認 KPI と閾値つき、3 件まで)。計算機が「保留をすべて C」の感応度を出す | gate conditions / valuate.py |

## B. 数字の時点と出所(facts.py・lint_deck.py が守る)

| # | 規則 | 誤りの例 | 正しいやり方 | どこで止まるか |
|---|---|---|---|---|
| B1 | 数字には時点を付ける | Q3 の資料に Q2 の預金 455 億ドルが時点なしで残った | 台帳の period。前の四半期の値は「(Q2)」を付けて比較に使う | facts.py / lint_deck.py(古い時点) |
| B2 | 未確認の数字を使わない | 出所が不明な報道の「流通額 約 3 億ドル」を載せた | T4 は not_for_deck。資料に混ざれば検査で止まる | facts.py / lint_deck.py(未確認) |
| B3 | 基準を混ぜない | GAAP の前年比と調整後の前年比を同じ表で比べた | 台帳の basis。比べるときは同じ基準どうし | 自分で確かめる |
| B4 | 決算が出たら仮説を答え合わせして直す | 外れた仮説(販促費を削って EPS を作る)を残した | 当たり・外れ・一部・未確認の表を作り、外れは示唆ごと直す。直した項目の一覧は資料に書かない | 自分で確かめる |
| B5 | 版の言葉を書かない | 「第3版から変更」「前回」と資料に書いた | 最終版として最初から出す | lint_deck.py / gate report |

## C. 分析の規律(自分で確かめる。各工程の終わりに読む)

| # | 規則 | 誤りの例 | 正しいやり方 |
|---|---|---|---|
| C1 | 成長企業はフェーズを最初に決め、現在と将来の二層で評価する | 今の ROTCE の低さだけで条件2 を C にした | growth-stage-evaluation §1・§2。将来の評価には実現確率を付ける(gate conditions が future_grade を求める) |
| C2 | KPI は前期比・前年比の率の推移で読む | 純増の数だけ見て「減速」と書いた | 率(前年比・前期比の年率)と 2 階の差で、加速・減速を言う |
| C3 | EPS の四半期は税・株数・一時要因に分ける | 税率が 6% → 23% に上がったのに「利益が鈍った」と書いた | 税引前・税率・株数・一時要因の 4 つに分けて、どれが動いたかを書く |
| C4 | フライホイールとバリューチェーンは競合と比べて数字で確かめる | 「好循環がある」とだけ書いた | 会員 1 人当たりの収益・製品数・獲得費を、同業と並べる |
| C5 | 資本モデルは業界と比べてから評価する | 71% の保有を「景気循環型」と決めつけた | 銀行の標準・マーケットプレイスと並べ、利点・欠点を数える |
| C6 | 信用と資本の制約は同業と比べて数量化する | 「資本が足りない」とだけ書いた | 下限までの余裕・何四半期で届くか・増資 1 回の希薄化を数字で。株価が示す損失率を逆算して同業の最悪期と比べる |
| C7 | マクロ要因は両面で合計し、市場の織り込みと比べる | 金利上昇の評価減だけを数えた | +100bp の NII・貸倒・評価減・資本コストを 1 株当たりで合計し、株価の下落と比べる |
| C8 | 条件6 は市場・同業との乖離で評価する | 閾値を満たしたので S とした | 閾値を満たせば B(A 寄り)から出発し、乖離で A まで上げる。条件7 が C 以下なら S は無効 |
| C9 | 経営者(条件5)は経歴とその事業への経験で評価する | 「信頼できる」とだけ書いた | 経歴 → 現職 → 担う事業 → 結果(公約と実績)の順に書く |
| C10 | 原因は 2 層以上たどる | 「販促費が増えたから」で止めた | 観測 → なぜ(1 層)→ なぜ(2 層)を書き、各層が何を指すかを書く |
| C11 | 市場との差分と優位の種類を書く | 結論が「割安」だけ | 市場の仮説(出典)と構造上の見方の差、優位の種類(情報・分析・時間軸・行動)。無ければ「エッジなし」(gate report) |
| C12 | 示唆を 1 つ以上出す | 初歩の分析で終わった | 市場が値段に入れていない因果を、確認 KPI と時期つきで 1 つ以上(growth-stage-evaluation §14) |
| C13 | 固有性テスト | 社名を替えても成り立つ文を結論にした | その会社の数字と仕組みでしか言えない文にする |
