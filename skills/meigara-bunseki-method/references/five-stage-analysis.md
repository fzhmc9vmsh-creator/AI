## §0 骨組みと一貫性の鎖

| 工程 | 問い | 出すもの(台帳) | 次の工程へ渡すもの |
|---|---|---|---|
| 0 前提 | 何者で、業界のどこにいるか | `business_map.json` の `industry`・`glossary` | 用語と登場人物 |
| 1 現在の構造 | どの製品で稼ぎ、現金はどこで生まれどこへ投じるか | `business_map.json` の `portfolio`・`cash_map`(と既存の製品群の地図・バリューチェーン) | 今の EPS とその中身(製品群ごとの売上・利益・現金) |
| 2 将来の構造 | 会社の目指す構造はどこまで確かか。会社の計画の外で何が起きるか | `outlook.json` の `horizon`・`company_plan`・`market_scenarios`・`eps_lines`・`future_structure` | 年度別 EPS(会社計画・確度調整・選んだシナリオ)と成長率 g |
| 3 リスク | 何が起きると価値が崩れ、どれくらい起きやすいか | `outlook.json` の `risks` | 確率と影響(価値評価の木・感応度・EPS の調整) |
| 4 今の値段 | 今の株価は何を前提にしているか | `outlook.json` の `market_valuation`・`benchmarks`、`valuation.json` の `mkt.*` | 今の PER・今の PEG・株価が前提にする成長率 |
| 5 判定 | 今の株価は妥当か | `valuation.json`(許容 PEG・適正株価・判断)、`conditions.json` | 判断・価格帯・判別 KPI |

**一貫性の鎖**: 1 の今の EPS → 2 の道筋が作る年度別 EPS → 3 のリスクを確率で入れた EPS → 5 の g(3 年の EPS 成長率)と適正株価。
4 の今の PER は同じ EPS の定義(希薄化後・同じ年度)で出す。`valuate.py` は、採用経路の EPS から g・今の PEG・株価が前提にする成長率を
1 回で出す(`mkt.*`)ので、手で別の EPS を使わない。**5 で使う数字は、1〜4 で出した数字の組み合わせだけ。**新しい事実を 5 で初めて出さない。

## §1 現在の構造(1 工程)

### 1-1 製品ポートフォリオ × 製品ライフサイクル(PLC)

製品群(報告売上の 90% 以上)ごとに、`business_map.json` の `portfolio` に書く。

| 項目 | 書き方 | 出所 |
|---|---|---|
| `market_growth` | その製品の市場の伸び(今後 5 年の年率 %) | 調査会社・顧客の業界の開示。2 つ以上が望ましい |
| `position` | `{metric, value}`。原則は相対シェア(自社 ÷ 最大の競合。1 超なら首位)。シェアが取れないときは収益性(製品群の利益率)などで代え、`metric` に何を使ったかを書く | シェア調査・競合の開示 |
| `revenue`・`margin` | 製品群の売上(資料の単位)と利益率 | セグメント情報・説明資料 |
| `plc` | 導入・成長・成熟・衰退 | 判定の目安: 導入 = 売上が小さく赤字、伸びが不安定 / 成長 = 市場の伸び 10% 超で、投資が現金の創出を上回る / 成熟 = 伸び 5% 以下で、現金の創出が投資を上回る / 衰退 = 数量が減る |
| `cash_role` | 創出・消費・均衡 | 製品群の利益 − その製品群に要る投資(設備・研究開発・販促)。配賦の前提を `cash_basis` に書く |
| `next5y` | 5 年後の位置(`{market_growth, position}`)と動きの理由 | 2 工程の道筋から |

読み方: 成熟した「金のなる木」(伸び低・強さ高)が生む現金が、「花形」(伸び高・強さ高)と「問題児」(伸び高・強さ低)の投資に回る構造かを見る。
問題児が花形に移れる条件(シェアの閾値・設備の完工)と時期を書く。負け犬(伸び低・強さ低)は縮小か撤退かの判断を書く。

### 1-2 キャッシュの創出と投下(どこで生み、どこへ投じ、どちらが先か)

`business_map.json` の `cash_map` に書く。**「この会社は現金が先行する事業か、投資が先行する事業か」を一文で言い切る(`timing.one_line`)。**

| 項目 | 中身 |
|---|---|
| `sources` | 現金を生む所(製品群ごと。営業 CF の内訳の推計。合計は営業 CF と合わせる) |
| `uses` | 投じる所(維持更新の投資・成長の投資・研究開発・買収・株主還元・長期の支払い義務の消化) |
| `timing.type` | 前受け型(顧客の前払い・契約残高で、現金が利益より先に入る)/ 後払い型(売掛金・在庫が長く、利益より現金が遅れる)/ 投資先行型(設備・長期の購入義務が売上より先に出る)/ 中立 |
| `timing.metrics` | 型を示す数字 2 つ以上: 前受金 ÷ 売上、契約残高(RPO)÷ 売上、運転資本の回転日数(CCC)、支払い義務 ÷ 年間売上、投資の回収年数、営業 CF ÷ 営業利益 |

Anthropic の例: 営業 CF は 9 か月で +6,569 百万ドルと黒字だが、計算資源の支払い義務 900,900 百万ドル(自己資本の 8.11 倍)が売上より先に積み上がる
→ 投資先行型。需要が鈍ると義務だけが残る(3 工程のリスクの上位に入る)。

### 1-3 資本の構造と優位

貸借対照表で「何に資本を寝かせ、誰の資金で賄うか」(顧客の前払い・負債・株主)。オフバランスの義務は別に書く。優位(なぜ奪われないか)と ROE の
デュポン分解は、既存の手順(analysis-playbook §4、business-understanding 第3部)のまま。

## §2 将来の構造(2 工程)

### 2-1 目標の年(`horizon`)

将来の構造を描く年と、なぜその年かを書く(会社の計画の最終年・設備の完工・契約の満期・特許の切れ目)。理由の無い「5 年後」にしない。

### 2-2 会社の目指す構造と、ピースの確度 × 影響度(`company_plan`)

経営陣シナリオ台帳(scenario-strategy.md §0)のピースを、同じ物差しで採点する。

| 物差し | 定義(資料全体で 1 つ) |
|---|---|
| 確度 `p` | 目標の年までに、計画どおりに効く確率。高 = 0.7 以上(契約済み・完工済み・数字に出始めた)/ 中 = 0.4〜0.7(計画と一部の実績)/ 低 = 0.4 未満(構想のみ)。`certainty_basis` に根拠(基準率・契約・進捗の数字) |
| 影響 `impact_pct` | 計画どおりに効いたときの理論株価の変化(%)。`valuate.py` の感応度で出す(手で見積もらない)。大 = ±10% 以上 / 中 = ±3〜10% / 小 = ±3% 未満 |
| `statement` | 主に効く財務: PL(損益)・CF・BS・VC(バリューチェーン)・ROE |

**確度の低いピースを、会社の数字のまま将来に入れない。**確度調整後の EPS(`eps_lines.adjusted`)は、ピースの効きに確度を掛けて作る。

### 2-3 市場の脅威と機会(`market_scenarios`)― 会社の計画の外

競合の価格・技術の置き換え・規制・需要の変化・供給の変化など、**会社の計画に書かれていないこと**を、ピースと同じ物差しで並べる。脅威と機会の両方を
1 つ以上。**確度 0.4 以上かつ影響が大(±10% 以上)のシナリオは「選ぶ」(`chosen: true`)**: 選んだシナリオは、年度別 EPS(`eps_lines.scenario`)と
将来の構造の図に入れる。選ばないときは `reason_not` に理由。

### 2-4 道筋(`eps_lines`)と終点(`future_structure`)

- 道筋: 1 工程と同じ分け方(製品群)で、売上 = 数量 × 単価 → 費用率 → 営業利益 → 税・株数 → EPS を年度ごとに通す。3 本(会社の計画どおり・確度調整・
  選んだシナリオ)を `valuation_input.json` の `eps_paths` に同じ名前で入れる(`eps_lines` に名前を書き、gate が照合する)。
- 終点: P/L・CF・B/S・VC・ROE のうち**最も変わるもの**(`most_changed`)を、今と同じ型で並べる。なぜそれが最も変わるかを `why` に。
  道筋の数字が終点にそのまま着地すること(終点を先に描いて、理由付けを後で探さない)。

## §3 リスク(3 工程)― 確率 × 影響度

`outlook.json` の `risks` に 5〜8 個。

| 項目 | 書き方 |
|---|---|
| `p` | 目標の年までに起きる確率(0〜1)。**基準率から置く**(`p_basis`: 同じ条件で過去に何回中何回。数字を入れる) |
| `impact_pct` | 起きたときの理論株価の変化(%)。`valuate.py` の感応度・節点ツリーで出す |
| 期待損失 | `p × |impact_pct|`(gate が計算して順位を出す) |
| `reflected_in` | 価値評価への入れ方: tree(節点ツリー)・sensitivity(感応度)・eps_path(EPS の経路を下げた)・未反映(理由を `reason`) |
| `signal_kpi`・`threshold`・`check_date` | 兆候の KPI、見直しの線、確認日 |

- 期待損失の上位 3 個は、必ず価値評価に入れる(未反映にしない)。
- 確率が低く(10% 未満)影響が大きい(30% 以上)ものはテールとして分け、兆候のトリガーだけを置く。
- 期待損失の 1 位が価値の芯(感応度 1 位)と違うときは、なぜかを書く(多くの場合、同じ変数に行き着く)。

## §4 今の値段(4 工程)― 株価は何を前提にしているか

- `valuate.py` が採用経路の EPS から出す: 今の PER(`mkt.per.<価格>` = 株価 ÷ 評価の初年度の EPS。`eps_ntm` を入れればそれを使う)、
  今の PEG(`mkt.peg.<経路>.<価格>` = 今の PER ÷ (g × 100)。g は評価の初年度からの 3 年の EPS 成長率)、株価が前提にする成長率
  (`mkt.implied_g.<価格>` = 許容 PEG で正当化するのに要る g、`mkt.implied_g_peg10.<価格>` = PEG 1.0 で要る g)。
- 市場の前提と自分の見立ての差分の表(`thesis.variant`)は、この数字で書く。
- **同業との比較は「比較の設計」(`benchmarks`)を先に決める**:
  1. 指標(`metric`)と定義(`definition`)、何を判断するための指標か(`purpose`)。
  2. なぜその軸か(`why_axis`): 価値の芯(感応度 1 位の変数)に効く指標か。効かない指標で比べない。
  3. 比較対象(`peers`)は、**その指標を動かす仕組みが同じ会社**(費用構造・顧客・成長段階)。会社ごとに「何の会社か」(`what`)と「なぜ比べるか」(`why_comparable`)。
  4. 外した候補と理由(`rejected`)。突っ込まれたときの答え。
  旧版の誤り: 研究開発費率の将来を、データ基盤のソフトウェア会社(SNOW・DDOG)の実績と比べた。モデルの学習費が研究開発に入る会社と、入らない会社では、
  比率が下がる仕組みが違う。比べるなら仕組みが同じ会社か、仕組みの違いを限界として明記する。

## §5 判定(5 工程)

1. **PEG の照合**: 今の PEG(4 工程)と、構造評価(13 条件)から出る許容 PEG(`peg.start`)を比べる。今の PEG が許容を上回れば、値段は成長に対して高い。
   g は 2 工程の道筋に 3 工程のリスクを入れた採用経路の EPS から(`valuate.py` が同じ EPS で両方を出す)。
2. **適正株価と価値の橋**: 年度別の表(EPS・g・許容 PEG・妥当 PER・適正株価)と、今の株価 → 今の利益が続く場合 → 成長の上乗せ → 適正株価。
3. **13 条件の照合**: 各条件の根拠を、1〜4 工程のどの分析から引いたかを `evidence` の台帳の id と、報告書の節の番号で示す。
4. **投資行動**: 判断・価格帯・判別 KPI・確認日・撤回の線(`thesis`)。

## §6 用語(`business_map.json` の `glossary`)

資料・報告書に出る専門用語・略語を全部、`{term, plain, why}` で書く(意味と、この分析でなぜ要るか)。報告書は初出で一言定義し、資料は
bcg-slide-method の `storyline.json` の `glossary` にそのまま写す(`L.termNotes` と照合)。社内の記号(示唆の番号・反論の番号・ゾーンの記号・
評価の分布)は、報告書と資料の本文に出さない(台帳の中だけで使う)。
