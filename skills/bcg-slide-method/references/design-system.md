# デザインシステム(数値仕様)

すべての実装はこのファイルの**定数**に従う。「だいたい中央」「いい感じの緑」は禁止。
ここにない値を使う場合は、設計書に理由を明記する(監査L2で照合される)。

## 1. キャンバスとゾーングリッド(16:9)

- スライドサイズ: **33.867cm × 19.05cm**(13.333in × 7.5in)。python-pptx:
  `prs.slide_width = Emu(12192000)`, `prs.slide_height = Emu(6858000)`
- 左右マージン: **1.2cm** / 上マージン: **0.7cm** / 下マージン: **0.55cm**
  (=19.05−出所行下端18.5)
- コンテンツ幅: 31.47cm(= 33.867 − 1.2×2)

### 標準ゾーン(y座標は上端からのcm)

| ゾーン | y範囲 | 内容 |
|---|---|---|
| タグ帯(任意) | 0.7–1.3 | 緑ベタ白抜きの位置づけタグ(「グッドプラクティス」等) |
| メッセージライン | 1.4–3.2 | 緑・最大2行。タグなしの場合は 0.9–2.7 に繰り上げ |
| リード文(任意) | 3.2–3.8 | 黒・1行。タグなしの場合は 2.7–3.3 に繰り上げ(ボディ上端4.2は固定) |
| ボディ | 4.2–16.9 | 図解本体。**この範囲からはみ出したら監査で差し戻し** |
| 脚注 | 17.0–17.9 | 上に細いグレー罫線(0.5pt, #BFBFBF)を引いてから脚注 |
| 出所行 | 17.9–18.5 | 「Source: …」左寄せ |
| ページ番号 | 17.9–18.5 | 右端(右揃え、右マージン内) |
| 章ラベル(任意) | 0.5–1.2 右上 | 現在の章名(右揃え)またはナビサムネ |

- 脚注・出所がないスライドではボディを 17.9 まで拡張してよい
- メッセージライン・リード文の幅は最大 26.5cm(x: 1.2–27.7)。右上の章ラベル/
  ナビサムネ(x: 28.2–32.667)と水平に重ねない
- **表紙**: グリッド適用外。タイトル24pt太字TEXTを縦中央(y 8.0–11.0)、その下に
  日付・作成者9pt GRAY_TEXT。左端に縦帯(x 1.2–1.5、y 8.0–11.0、GREEN)を添える
- **章扉**: 章番号(GREEN太字30pt)+章タイトル(TEXT太字20pt)を y 8.0–11.0 に左寄せ、
  表紙と同じ縦帯。フッター(ページ番号)は本編グリッドを維持
- **機密表記**(Phase 0で要とされた場合): 「Confidential」8pt GRAY_TEXT、
  出所行と同じy(17.9–18.5)に中央揃え。全スライド同位置

### 配置の規則

- **整列**: 同種要素のx座標・幅・高さは完全一致させる(1mm単位で)。等間隔配置は
  間隔値を変数で一元管理する
- **カラム分割(等幅)**: ボディをn分割する場合の列幅 = (31.47 − 0.5×(n−1)) / n
  (列間ガター0.5cm)
- **カラム分割(非対称)**: 「ラベル列+本文列」構成(P-14等)はラベル列4.5cm+
  ガター0.5cm+本文列26.47cm。3列非対称(ラベル+2観点列)はラベル4.5cm+
  観点列(31.47−4.5−0.5×2)/2=12.985cm(≒13.0cm)ずつ
- **余白の規律**: 余白は「ゾーンとゾーンの間」に規則的に取る(ガター0.5cm、パネル間、
  表の行間)。**証拠を削って面としての空白を作らない** — BCG級の密度基準
  (density-composition.md §1)が優先。悪い余白=何も置かれていない大きな面、
  良い余白=高密度な要素群の間の呼吸。メッセージと無関係な要素で埋めるのも禁止

### チャート系列の配色(比例描画チャート専用ランプ)

系列数に応じて上から順に使う(意味の重い系列ほど濃く):
1系列: GREEN / 2系列: NAVY+GREEN / 3系列: NAVY+GREEN+GREEN_PALE2 /
4系列以上: NAVY→GREEN_DARK→GREEN→GREEN_MID→GREEN_PALE2→LIME→GRAY_LINE(その他は常に
GRAY_LINE)。100%積み上げの「その他/others」は必ず最薄(GRAY_LINEまたはGREEN_PALE2)。
非強調の比較対象バーはGRAY_DARK/GRAY_LINEに落とす(強調1箇所の原則はチャートにも適用)。

### 使用規則

1. 1スライドの色数は **緑系+グレー系+状態色(LIME/YELLOW)+強調(BLUE_BOX)+
   リスクマーカー(RISK_PINK)まで**。これ以外の色(紫・オレンジ等)を追加しない
2. 減少・マイナスの数値は赤を使わず、GRAY_DARK+「▲」表記で示す(▲12%)。
   RISK_PINKは「リスク・警告の位置を指す小さなマーカー」専用で、数値・本文・面には使わない
3. **色の意味語彙を固定する**: 緑=推奨・重点・実施 / 黄=注目・オプション・条件付き /
   ピンク=リスク / グレー=非強調・既存 / 点線枠=域外・参考・将来。資料全体で意味を変えない
4. 強調は1スライド1箇所: BLUE_BOX枠 or GREEN塗り(非強調をグレーに落とす)のどちらか。
   ※**同一の意味を持つ項目群への同色地は「1つの強調テーマ」=1箇所と数える**
   (例: オーバーレイ再掲のYELLOW_HLハイライト群、R10オプションリストのYELLOW_HL地、
   状態マトリクスの状態色群)。意味の異なる強調を2種類置くことが禁止事項
5. グラデーション・影・3D・テクスチャは全面禁止
6. 状態色の意味は資料全体で固定(凡例で一度定義したら変えない)

## 4. テキスト量の事前検算(オーバーフロー防止)

日本語全角1文字の幅 ≈ フォントサイズ(pt) × 0.0353cm。

```
1行に入る全角文字数 = floor(ボックス幅cm ÷ (pt × 0.0353)) − 2(パディング分)
必要行数 = ceil(文字数 ÷ 1行文字数)
必要ボックス高さcm = 行数 × pt × 0.0353 × 行間1.2 + 0.2(上下パディング)
```

**すべてのテキストボックスは、配置前にこの検算を行い、収まらない文はこの時点で短縮する。**
**ボックス高さにデフォルト値・一律値(例: 1.03cm)を使うことを禁止する** — 高さは常に
上式で内容から計算し、縦積みのピッチは「上のボックスの計算高さ+0.1cm」以上を取る
(blueprints.md「テキストボックスの高さ・積み上げの絶対規則」)。
python-pptx の `word_wrap = True` に頼った成り行き折返しで作らない(行の途中で
不自然に折れて可読性が落ちる。長文は自分で読点位置に改行を入れる)。

## 5. 共通部品の仕様

- **タグ帯**: 角丸なし矩形 GREEN塗り、高さ0.6cm、幅=文字数に応じ(文字数×0.353+0.8)cm、
  左端 x=1.2
- **チェブロン(矢羽)**: 高さ1.0cm、GREEN塗り(工程の大分類)、白太字12pt中央揃え。
  python-pptx: `MSO_SHAPE.CHEVRON`。n個並べる場合は等幅(幅=31.47/n cm)・隙間0で
  敷き詰める(CHEVRONは図形内で先端が食い込むため、ガター計算は適用しない)
- **主体ボックス**: 角丸矩形(角丸半径小)、GREEN_LIGHT塗り+GREEN枠1pt、10–11pt太字中央
- **統括帯(全体を貫く存在)**: 横長楕円または帯矩形、GRAY_DARK塗り、白太字12pt
- **番号バッジ**: 正円 直径0.7cm、GREEN塗り白抜き10pt太字(下段解説の番号と同一書式)。
  解説側は「番号円+緑太字見出し」を1行に並べる
- **矢印**: コネクタ直線+三角終端。主要=TEXT色1.5pt実線、補助=GRAY_LINE 1pt破線
- **チェックアイコン(R2型)**: 正円(OVAL)0.55cm。状態は GREEN塗り/LIME塗り/
  白地+GREEN枠1.25pt の3種。チェック記号はMSO_SHAPEに存在しないため、
  円のテキストフレームにUnicode「✓」(白、枠のみの円ではGREEN、9pt太字、中央揃え)を置く
- **凡例**: マトリクス系(P-2/P-3/P-12)は列ヘッダ直上の右寄せ、それ以外はボディ右上。
  「凡例:」+アイコン+定義文9pt。枠線細グレー(GRAY_LINE 0.75pt)
- **強調枠**: BLUE_BOX 2.25pt枠、塗りなし、対象より上下左右+0.15cmの余裕で囲う
- **キッカー(章内トピックラベル)**: メッセージラインの上または左上に、小さな
  白地+GREEN枠0.75ptの矩形ラベル(9pt GREEN、例「C. グリーン国債における投資家構成」)。
  タグ帯(緑ベタ)は「位置づけの宣言」、キッカーは「章内の現在地」と使い分ける
- **示唆カラム(C-1)**: ボディ右端 幅6.5cm(x 26.17–32.667)。左の事実ゾーンとの間に
  ガター0.5cm。上端に小さな緑の連結マーク(▶または円弧矢印)。箇条書き2〜4個、
  各30〜70字、10pt。背景は白のまま(枠・塗りなし)で、左ゾーンとの視覚差は余白で作る
- **コールアウト帯(C-2)**: 表の右端に幅4.5〜6cmの縦長角丸矩形、GREEN_LIGHT塗り+
  GREEN枠1pt。中に10.5pt TEXTで50〜80字。上下は表と同じ高さに揃える
- **チップ(P-16)**: 幅2.2〜3.4cm×高さ0.7cm の小矩形、9pt中央揃え、塗り=所属状態
  (GREEN_LIGHT/グレー系)。同一列のチップはx・幅を揃えて縦に積む
- **行グループブラケット(P-15)**: 表の左端に回転テキスト(9pt太字)+波括弧図形
  (MSO_SHAPE.LEFT_BRACE)または細縦帯で行グループを束ねる
- **結論バナー**: ボディ最下部(y15.7〜16.9)の全幅帯(x1.2 w31.47 h1.0〜1.2)。
  GREEN塗り+白12pt太字中央揃え。図の下に「で、どうするか」を1文で置く(≤45字)
- **リスクマーカー**: 角丸小矩形 w1.1×h0.45、RISK_PINK塗り、白8pt太字中央「リスク」。
  図中の該当箇所の縁に重ねて置く(本文への重なり10%未満は監査許可リスト対象)
- **ローマ数字/丸数字バッジ(対応参照)**: 円0.55、GREEN塗り白9pt太字(ⅰ〜ⅴ/①〜⑱ 等)。
  図側とリスト側に同番号を置いて対応させる(番号ストーリー注釈の変種)
- **点線枠ボックス**: GRAY_LINE 1pt破線枠・塗りなし。意味=「域外・参考・将来・対象外」専用
- **矢印ラベル**: フロー矢印には必ず名詞ラベル(8.5pt、白地に置いて線と重ねない)。
  「何が流れるか」(融資/出資/電力供給/原料供給/fee 等)を書かない矢印を禁止する
- **脚注罫線**: y=17.0 に幅31.47cmの水平線 0.5pt GRAY_LINE
- **出所行**: 「Source: XXX」または「出所: XXX」8pt GRAY_TEXT。複数出所は「; 」区切り
- **ナビサムネ(章構造)**: 右上 x 28.2–32.667、y 0.5–1.2 の範囲に全章のミニ矩形列
  (各0.5×0.35cm、間隔0.1cm、右端揃え、GRAY_LINE枠)、現在章のみGREEN_LIGHT塗り。
  または同範囲に章名テキスト(9pt GRAY_TEXT右揃え)のみでも可

## 6. python-pptx 実装規約

1. 冒頭で定数を宣言し、**全shapeが定数を参照**する:
   ```python
   from pptx.util import Cm, Pt, Emu
   from pptx.dml.color import RGBColor
   GREEN = RGBColor(0x00, 0x9A, 0x44)  # 以下パレット全部
   M_L = Cm(1.2); BODY_TOP = Cm(4.2); BODY_BOTTOM = Cm(16.9)
   ```
2. 共通部品(メッセージライン、タグ、脚注、出所、ページ番号、凡例)は**関数化**して
   全スライドで同一座標に置く(`add_message_line(slide, text, lead=None)` 等)
3. スライドはブランクレイアウト(`slide_layouts[6]`)から組む。テンプレの
   プレースホルダは使わない(位置が制御できないため)
4. テキストは `text_frame.word_wrap = True`、`auto_size = None`。
   フォントは run 単位で `font.name` を設定し、**East Asianフォントも設定する**:
   ```python
   from pptx.oxml.ns import qn
   rPr = run._r.get_or_add_rPr()
   ea = rPr.makeelement(qn('a:ea'), {'typeface': FONT_NAME}); rPr.append(ea)
   ```
5. 図形の重なり順は「背景帯→ボックス→矢印→バッジ→テキスト」の順に add する
6. グラフは matplotlib で描いて画像貼付**しない**。矩形図形の手組み(§7)または
   pptxネイティブチャートで作る(後から編集可能に保つ)
7. 1スライド1関数(`def slide_03(prs, ...):`)。マジックナンバーを関数内に散らさない

## 6.5 PowerShell(Office COM)実装の注意(python-pptxが使えない環境)

実機テストで全面崩壊を引き起こした既知の罠。COM実装では必ず守ること:

1. **変数名の大文字小文字は区別されない**: `function Pt([double]$cm){ $cm * $CM }` は
   `$cm`と`$CM`が同一変数になり座標が2乗されて全崩壊する。定数は`$PT_PER_CM`のように
   パラメータと衝突しない名前にする(1cm=28.3465pt)
2. **AutoSize=0でも高さが勝手に固定される**: テキスト設定時に既定フォントで一度だけ
   暗黙リフローが走り、高さが約1.03cm(既定1行分)に固定される。**テキスト・フォントを
   すべて設定し終えた後に Height(と念のためLeft/Top/Width)を明示的に再代入**して確定する
3. 日本語はBOM付きUTF-8の.ps1に書いて実行(コマンドライン直渡し禁止)。`$`はバッククォートで
   エスケープ。`Font.Size`は[float]キャスト。色は `R + G*256 + B*65536`。msoTrue=-1/msoFalse=0
4. PNG出力は `Slide.Export "path.png", "PNG", 1920, 1080`(L3視覚監査に必須)。
   終了時は必ず `Presentation.Close` と `Application.Quit`(プロセス残留防止)

## 7. 比例描画チャートの作図仕様(手組み)

**「数値をテキストで書く」ことと「チャートを描く」ことは別物**(density-composition.md
§1.5)。手組みチャートは以下の手順で、必ず幾何を数値から計算して描く:

### 縦棒(P-5)
```
プロット領域: 幅W×高さH を決める(例 H=8.0cm)
スケール: scale = H / max(値)     ※軸はゼロ始まり
各バー: 高さ = 値×scale、幅 = W/(本数×1.6)、等間隔配置
データラベル: バー上端の上0.15cmに 9-10pt太字で値+単位(全バーに打つ)
カテゴリラベル: バー下端の下に10pt
基線: プロット領域下端に0.75pt TEXT色の水平線(Y軸目盛・グリッド線は省略が既定)
```

### 100%積み上げ棒(R5型・構成比)
```
各バー: 全高Hを固定(例6.0cm)。セグメント高 = H×構成比(上から意味の重い順)
セグメント色: チャート系列ランプ(§2)。隣接セグメントは白の区切り線0.75pt
セグメント内ラベル: 高さ0.55cm以上のセグメントには中央に%を直接置く
  (濃色セグメント=白抜き9pt太字、薄色=TEXT色)。小さすぎるセグメントは
  引出線で外側に置くか省略(省略は5%未満のみ可)
複数バーの小マルチ: 全バーで同一の高さ・幅・y位置。凡例は下段に1つだけ
```

### ウォーターフォール(P-6)
```
累積値を計算し、各バーの下端 = min(累積前, 累積後)×scale、高さ = |増減|×scale
バー間を点線コネクタ(GRAY_LINE 0.75pt)で水平接続
各バーに増減額(+/▲付き)を上端に表示、始点・終点バーには合計値を太字で
```

### 折れ線(P-7)
```
点座標: x = 左端 + i×(W/(n-1))、y = 下端 − 値×scale を計算し、
フリーフォーム(add_freeform)または直線コネクタの連結で描く。線2pt
実線=実績/破線=予測。終端に値+系列名ラベル(凡例より優先)
```

### 共通規律
- 全チャートに単位表記(軸ラベルまたはタイトル脇: 「(億円)」「(%)」)
- 値がテキストとしても図形位置としても仕様どおりかを監査L2で照合できるよう、
  実装コードに `values = {...}` のデータ辞書を残す(ハードコードで座標だけ書かない)
- 3対象×2チャートのような小マルチ構成では、列のx座標を表・チャート間で共有する変数にする
