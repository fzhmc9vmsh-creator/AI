# 表現パターンライブラリと選択決定木

「この文章をどの図解で表現するか」を決めるためのリファレンス。
冒頭の基準スライドR1〜R11は実在のBCG資料12枚をテキスト仕様化したもので、本スキルの品質バー
(R11には再掲オーバーレイ技法が付随する)。
**新しいスライドを設計するときは、まず「R1〜R11のどれに最も近いか」を判定する。**
R対応のあるパターン(P-1〜P-4=R1〜R4、P-15=R7、P-16=R8、P-17=R9、P-18=R10、
P-19=R11、および決定木が直接出力する「R5型」「R6型」)に該当すれば
そのR番号を設計書に記す。該当しない場合は
パターン集(P-5〜P-14)から選び、「R対応なし・P-x準拠」+選択理由を記す
(無理にRへの類似をこじつけない)。
**本ファイルのR記述は「意味と使い分け」の理解用。実装時の座標・寸法・スロット上限は
blueprints.md のshape表が正**であり、食い違いがあればblueprints.mdに従う。

## 基準スライド仕様(実在BCG資料より)

### R1: プロセスフロー+番号注釈型(グッドプラクティス紹介)

**メッセージ例**: 「先端企業ではコントロールセンターにリアルタイムで集約化されたデータを
元に、迅速な意思決定を実施し、柔軟性の高いオペレーションを展開している」
**リード文**: 「製造業E社におけるフレキシブルなサプライチェーン全体オペレーション構築」

**構造(上から)**:
1. 左上に小さな緑ベタ白抜きタグ「グッドプラクティス」(事例の位置づけラベル)
2. 緑のメッセージライン2行 + 黒のリード文1行
3. ボディ上段(y 4.2–11.2cm、高さ7.0cm): 横方向プロセスフロー
   - 最上部: 3つの矢羽(チェブロン)「作る」「運ぶ」「売る」が横幅いっぱいに並び工程の大分類を示す
   - その直下: 横長の濃グレー楕円「コントロールセンター」が全工程を貫く(=全体を統括する
     存在は「貫く帯」で表現する)
   - 中段: 工程ごとの主体ボックス(製造拠点→船便/航空便→配送拠点→店舗チャネル/自社EC/別地域)。
     薄緑塗り+緑枠の角丸矩形。実線矢印=主ルート、破線矢印=代替・サブルート
   - 各ボックスの上に、そこで管理するデータ項目を小さな箇条書き(生産計画・調達計画…)で添える
   - フロー上の意思決定ポイントに**番号つき円バッジ(1〜8)**を配置
4. ボディ下段(y 11.4–16.9cm、高さ5.5cm): 番号に対応する解説を工程の真下に列で配置。
   緑色の見出し(「1 生産計画最適化」)+黒の箇条書き詳細(2〜3行)
5. 最下部: 脚注(「1. Stock Keeping Unit; 2. プラットフォーム」)+出所行

**この型の本質**: 「図で全体像、番号で詳細」の2層構造。図中に長文を書き込まず、
番号で下段の解説に逃がすことで、図の視認性と情報量を両立する。

### R2: 状態マトリクス型(多対象×多観点の実施状況比較)

**メッセージ例**: 「国により実施している施策は異なるが、前述の4カテゴリで複合的に支援を行っている」

**構造**:
1. 緑のメッセージライン1行
2. 右上に凡例: 「✓(緑ベタ)=政府主導で実施、✓(黄緑ベタ)=州/自治体主導で実施、
   ✓(緑枠白抜き)=検討中」 — **状態は3値以内、アイコンの塗りと枠で区別**
3. マトリクス本体:
   - 列ヘッダ: 8カ国。国旗アイコン+「目指す姿」の短文(デジタル単一市場と新技術の主導的活用、等)。
     列ヘッダに「その列の性格づけ」を1行で書くのがBCG流
   - 行ヘッダ: 3階層(市場創生/市場規制 → 利用・プロダクト/技術・人材・政策 → 個別施策)。
     階層は左からの字下げ+縦の色帯(カテゴリごとに色相を変えた細い帯)で表現
   - セル: チェックアイコンのみ(補足文言を書かない。アイコン自体はUnicode「✓」で実装、
     design-system.md §5参照)。空セル=実施なし
4. 最下部: 「Source: 公開情報よりBCG作成」

**この型の本質**: 定性情報を「あり/なし/程度」の離散状態に落とし、面で俯瞰させる。
セルに文字を書かず、アイコン密度でパターン(どの国が厚いか)を読ませる。

### R3: 条件ヒートマトリクス型(セル内に結論+理由)

**メッセージ例**: 「なお、各使途のアプリケーション実現に必要な技術領域(インフラレイヤー)は
以下のとおり。特にセキュリティ/プライバシーは、何れの使途でも必要」

**構造**:
1. 緑のメッセージライン2行+「参考)」で始まる黒のリード文
2. マトリクス本体:
   - 列ヘッダ: 技術領域7列。緑の下線つき見出し+その技術の説明1〜2行(黒の小さい文字)
   - 行ヘッダ: 使途7行(青系の文字色で左に縦ラベル「ブロックチェーンの主な使途」)
   - セル: 2値の塗り分け — 緑塗り「**必要**(理由の短文)」/ 黄塗り「**あれば尚可**(理由の短文)」。
     該当なしは空白。セル内は「結論1語+カッコで理由」の形式に統一
3. **メッセージで指した列(セキュリティ/プライバシー)を水色の太枠で囲って強調** —
   メッセージと図の対応を枠強調で機械的に示す
4. 最下部: 出所行

**この型の本質**: R2との違いは「セルに理由まで書く」こと。読者が個別セルの根拠を
確認したい審査・要件定義系の内容に使う。強調枠がないR3は未完成(メッセージとの接続がない)。

### R4: フレームワーク表型(分類×観点の網羅整理)

**メッセージ例**: 「技術開発の推進には、ヒト・モノ・カネ・情報のリソースの確保と継続的な投下が必要」

**構造**:
1. 緑のメッセージライン1行
2. ボディ: 4行×2列の表
   - 行: ヒト/モノ/カネ/情報。左端に緑枠ボックス(アイコン+分類名)。
     アイコンは単色(緑系)のシンプルなピクトグラム
   - 列: 「What(何を)」「How(どのようにして)」。緑の下線つき列見出し
   - セル: 冒頭に要約1行+黒の箇条書き2〜3個(「〜等」で締め、網羅でなく例示であることを示す)
   - 行区切りは薄いグレー破線(実線の格子で埋めない=表を軽く見せる)
3. 最下部: ページ番号

**この型の本質**: フレームワーク(分類軸)で「モレなく考えた」ことを示す型。
分類(行)×問い(列)の2軸が決まれば中身は箇条書きでよく、作成コストが低い。
安易に多用しがちなので、「分類自体に意味がある」場合に限って使う。

### R5: ヘッダーファクト表+スモールマルチプル+示唆カラム型(多対象の定量比較)

**メッセージ例**: 「各国のグリーン国債の初回発行時の投資家の地域/タイプ別の保有率の比較」
(左上に小さな章キッカー「C. グリーン国債における投資家構成」)

**構造**:
1. 左上にキッカー(小さな枠ラベル)、その下にメッセージライン
2. ボディ左(約8割の幅): 4対象(EU/フランス/ドイツ/香港)を列に取り、
   - 上段ファクト表(4行): 国債名/ISINコード/初回発行日時/初回調達額 —
     **定性・定量の基本属性を表で先に見せてからチャートに入る**
   - 中段: 対象ごとの100%積み上げ棒「投資家の地域別内訳」(Europe/Asia/others、
     セグメント内に%を白抜きで全打ち: 98%、96%、100%、73%…)
   - 下段: 同じ列割りで「投資家のタイプ別内訳」(Asset Managers/Insurance・Pension/
     中銀/銀行/ヘッジファンド/Others の6セグメント)+下に凡例
   - 列の縦位置は表とチャートで完全に揃う
3. ボディ右(幅約6.5cm): 緑の連結マーク+示唆の箇条書き2個(「欧州は自地域の投資家が
   大半を占める一方、香港は…調達コスト低下を図っていると推察される」等、各50〜70字)
4. 最下部: Source行に**複数出所をURL・機関名付きで**列挙

**この型の本質**: 「事実(左)と解釈(右)の分離」。事実ゾーンは数値を全打ちした
高密度、解釈ゾーンは厳選した2〜3個の示唆。1枚で「データ確認」と「意味の理解」が完結する。
→ 複合構成 C-5 + C-1(density-composition.md)

### R6: 3パネル論点整理型(現象→メカニズム→検討の視点)

**メッセージ例**: 「新たな枠組を検討するに際しては、技術と事業の両面から、支援ニーズを
考えていく必要」+リード「考えるべきポイントの全体像」

**構造**:
1. ボディを3縦パネルに分割:
   - 左パネル(最大): 2軸マップ(縦=事業・投資環境の見通し(安定/不安定)、
     横=技術の成熟度 L/M/H)。既存の支援領域ボックス、目標状態「ビジネス自立」ボックス
     (右上、強調)、番号バッジ①②付きの移行矢印、「例: CCU、水素還元製鉄」等の実例注記
   - 中パネル: 鍵概念の分解「『死の谷』の橋渡しとは?」— 番号ブロック2個
     (①大規模な技術実証→技術プロバイダーへの支援 / ②構造的リスクの緩和→
     案件デベロッパーへの支援)。左パネルの①②と番号で対応
   - 右パネル: 「検討の視点」— A/B/C の緑丸ラベル付き問いボックス3個
     (対象技術/ファンディング手法/枠組デザイン、各に問いを2行)
2. パネル間は番号(①②)と文字(A/B/C)で相互参照し、矢印(▶)で読み順を示す

**この型の本質**: 1枚で「全体地図→鍵となる論理→次に議論すべき問い」まで運ぶ。
検討初期の議論用スライドの最強フォーマット。→ 複合構成 C-3

### R7: 高密度インベントリ表+コールアウト帯型(網羅リストで圧倒する)

**メッセージ例**: 「一方、技術成熟度とは別に、事業化には、ビジネス面で様々なリスクが存在」
+リード「事業開発に伴うビジネスリスク(例: インフラ事業の場合)」

**構造**:
1. ボディ左(約8割): リスク一覧表 約15行
   - 最左: 行グループの縦ブラケット(開業前/開業後/共通)— 回転テキスト+波括弧
   - 第2列: リスク分類の小ラベル(政治・制度リスク/ファイナンスリスク/アセットリスク/
     収益リスク…)— 分類ごとに背景色帯
   - 第3列: リスク項目名(許認可リスク、用地確保リスク…)
   - 第4列: リスク概要 — **全行に1行(25〜45字)の具体的説明**(「事前取得した建設・採掘
     等の許認可が取消・変更になるリスク」)
2. ボディ右(幅約5cm): 縦長の緑コールアウト帯 — この表のSo What
   (「技術成熟度の引き上げとは別に、リスクを緩和し、事業・投資環境の見通しをつける
   政府支援策も、企業の事業化を大きく左右する」)
3. Source: エキスパートインタビュー

**この型の本質**: 「網羅性の証明」。行数を恐れず15行載せ、全行に理由・説明を付ける。
ただし必ずコールアウト帯で「で、何が言いたいか」を1点に集約する。→ C-2

### R8: チップ・ポートフォリオマップ型(2軸に個別要素を配置)

**メッセージ例**: 「GI基金と分担し、大規模技術実証や、構造的なリスク緩和を行う支援策が重要」

**構造**:
1. 2軸フィールド: 横=技術の成熟度(L: TRL1-4, 研究・開発/M: TRL5-7, 実証/H: TRL8-9,
   事業化 — **軸ラベルに定義を併記**)、縦=事業・投資環境の見通し(安定/不安定)
2. フィールドに個別技術のチップ(小さな矩形、1個=1技術名)を10〜20個配置。
   チップの塗り分け=所属領域(既存基金の対象=グレー系、支援対象候補=緑系)
3. 領域を大きな枠(既存基金のカバー範囲、目標「ビジネス自立」領域)で囲い、
   番号バッジ①②+注記(「①大規模な技術実証」「②構造的リスクの緩和」)で
   移行ストーリーを重ねる
4. 例外・注意は左下の小さなグレー吹き出しで(「大きな経済負担、周辺地域への影響…」)
5. Note行(プロットの根拠・判定基準)+Source行

**この型の本質**: P-8(2×2)の高密度版。抽象的な象限でなく**実名のチップ**を敷き詰める
ことで、位置づけの議論を具体に落とす。チップの選定根拠をNoteに必ず書く。

### R9: ポジション図+属性表の複合型(構造の見立て+ディテール)

**メッセージ例**: 「EUは、様々な基金・プログラムにより基礎研究から事業化までを幅広くサポート」

**構造**:
1. ボディ左(幅約8cm): 技術成熟度スケール上の各基金の位置付け見立て(縦に並べた
   基金ボックス+カバー範囲のブラケット)
2. ボディ右(残り): 基金ごとの属性表 — 列: 目的/主な投資対象(例)/金額(億ユーロ)/
   投資スキーム。セルは箇条書き2〜4個、金額は右揃えの太字数字、スキームは短語
   (グラント、デットファイナンス、エクイティファイナンス…)
3. 左図の基金と右表の行は上下位置で対応(または線で接続)
4. 脚注(定義・出所条件)+Source(URL付き)

**この型の本質**: 「見立て(構造)」と「ディテール(属性)」の同居。読者は位置づけを
掴んでから詳細を検証できる。→ C-4の変形

### R10: ストラクチャー図(アクター相関・マネーフロー)+オプションリスト型

**メッセージ例**: 「基金・ファンドからの具体的な資金提供スキームには、いくつかのオプションが考えられる」

**構造**:
1. ボディ左(約6割): 事業スキームのアクター相関図
   - アクターを3層に配置: 上層=資金・支援の出し手(投資家・レンダー・補助/支援機関)、
     中層=事業主体(SPC/GP/LP等の中核ボックス、外周を点線枠で束ねる)、
     下層=取引相手(オフテイカー、EPC、OEM、O&M等)
   - アクター間を**ラベル付き矢印**で接続(融資/出資/金利/配当・キャッシュフロー/
     オフテイク契約・支払/電力供給/建設サービス/資機材・部品供給/fee — 何が流れるかを全矢印に明記)
   - リスクの所在に**RISK_PINKのリスクマーカー**を置く(リスクがどの契約・どの主体に
     たまるかを図上で示す)
   - 図中の主要な資金の入り口にローマ数字バッジ(ⅰ〜ⅴ)
2. ボディ右(約4割): オプションリスト — ⅰ〜ⅴに対応する黄色ハイライト(YELLOW_HL地)の
   項目ボックス縦積み。各「政府は**グラント(補助)**を提供し、事業全体の採算性を改善する」
   のように主語+手段太字+効果の1文
3. 最下部: **結論バナー**(緑帯白抜き)「いわゆる"ファンド(PE/VC)"の固定イメージに
   縛られない、柔軟な設計を行う必要」

**この型の本質**: 「構造の理解」と「打ち手の選択肢」を1枚で対応させる。カネ・契約・
モノの流れを描くとき、箇条書きでは絶対に出ない説得力が出る。M&A、事業スキーム、
資金調達、レバレッジ設計、業務委託構造など汎用性が非常に高い。

### R11: バリューチェーン俯瞰マップ(鳥の目)型

**メッセージ例**: 「脱炭素に関わる全体像(鳥の目)の構成」

**構造**:
1. 最上段: バリューチェーンの大工程チェブロン(エネルギーをつくる→モノをつくる・育てる→
   つかう→すてる)。各チェブロンに**シェア%バッジ**(日本の全CO2排出量に占める割合40%/29%/29%/2%)
   を付け、工程の重みを定量で示す
2. 各工程の直下: 構成要素のボックス群を縦積み(再エネ/化石燃料/原子力/アンモニア/水素…、
   製鉄/化学品/窯・土石/金属/木材・紙/繊維…、船舶/航空機/自動車/蓄電池/半導体/住宅…)。
   サブ工程(生成(海外)/輸送・発電(国内)等)は列を分けるか小見出しで区切る
3. 列と列の間: **供給関係の縦ラベル+矢印**(電力供給/水素・アンモニア供給/燃料供給/原料供給)
4. 海外・域外・参考の要素は**点線枠**で区別
5. 最下段: 全工程を貫く共通レイヤーの帯(CO2の排出・回収ループ等)
6. 一部の要素に%バッジ(物流・インフラ18%、業務その他6%等)を添えて濃淡を付ける

**この型の本質**: テーマの「全体地図」を1枚で定義する。以後の議論はすべてこの地図の上の
位置で語れるようになる。産業構造、業界バリューチェーン、家計の資産フロー、事業ポートフォリオ
など、あらゆるテーマの「第1章の1枚目」に使える。

### 再掲オーバーレイ技法(R11等のベースマップの再利用)

**メッセージ例**: 「現行プロジェクトは、グリーン成長戦略で成長が期待される14分野を手広くカバー」

R11で定義した全体地図を**同一座標のまま再掲**し、上に情報を重ねて別のメッセージを語る:
1. ベースマップは座標・構成を1mmも変えずに再描画(テンプレート関数化して使い回す)
2. 重ねるもの: 該当要素の**YELLOW_HLハイライト着色**+**丸数字バッジ(①〜⑱)**+
   注記(バッジに対応する短いラベル)+右上に凡例(「XX=対象分野、主要事業者」等)
3. メッセージとキッカーだけ差し替える
4. 禁止: ベースの座標変更・要素の増減(変えると「同じ地図」の効果が消える)

**効果**: 読者は2枚目以降を0秒で理解し始める(地図は既に頭に入っている)。
「全体像→現状カバレッジ→空白領域→提言領域」と同じ地図で3〜4枚語るのが定石。

## 表現パターン集(P-1〜P-19)

各パターン: 【使う条件=メッセージの論理型】【構造仕様】【近い基準】

### P-1 プロセスフロー+番号注釈(=R1)
- 条件: メッセージが「仕組み・流れ・オペレーション」を語る。「〜のプロセスで実現する」
  「〜が連携して動く」
- 仕様: R1準拠。工程チェブロン→主体ボックス→矢印(実線=主、破線=副)→番号バッジ→下段解説。
  貫通する統括者は横長帯/楕円で
- 番号バッジは最大8個。超えるなら2枚に割る

### P-2 状態マトリクス(=R2)
- 条件: 「AとBとCを、観点1〜nで比べると…」かつ各セルが2〜3値の状態に落ちる。
  比較対象3つ以上×観点3つ以上
- 仕様: R2準拠。凡例右上、状態3値以内、セルはアイコンのみ
- 対象2つの比較はP-11(Before/After・対比)を使う

### P-3 条件ヒートマトリクス(=R3)
- 条件: P-2と同じ比較構造だが、セルごとに理由・条件の説明が必要(審査、要件定義、適合性評価)
- 仕様: R3準拠。セル=結論1語+括弧理由、塗りは2値(必要=緑/条件付き=黄)、
  メッセージ該当箇所を強調枠
- セル文字は8pt以上を維持できる規模まで(目安: 7列×8行)。超えたら行を分割して2枚に

### P-4 フレームワーク表(=R4)
- 条件: 「〜にはX・Y・Zが必要」「〜をa/b/cの軸で整理する」網羅・分類のメッセージ
- 仕様: R4準拠。行=分類(3〜5個、アイコン付き)、列=問い(What/How、現状/課題/打ち手 など2〜3列)

### P-5 縦棒グラフ(推移・比較)
- 条件: 「Xは増えている/減っている」(時系列)、または「3対象以上を単一指標で比べると
  Aが最大」(大小比較)の規模と方向のメッセージ
- 仕様: 軸はゼロ始まり。系列は5本以内。メッセージの該当バーのみアクセント緑、他はグレー
  (**全部緑に塗らない — 強調は1箇所**)。データラベルは棒の上に直接置き、Y軸目盛は省略してよい
- CAGRや差分を語るなら、矢印+「+21.5%」注記を図中に描き込む

### P-6 ウォーターフォール(ギャップ・寄与分解)
- 条件: 「AからBへの差は、要因x・y・zで説明できる」「目標とのギャップは〜で埋める」
- 仕様: 始点・終点バーは濃グレー、増加要因は緑、減少要因は赤系ではなく**濃グレー+▲表記**
  (本スキルの配色では赤を多用しない)。各バーに金額と要因名。
  始点・終点は「実額の推移」(現状値→目標値)を原則とする(0→ギャップ額の表現より、
  前後スライドの数値と連続する実額を優先)
- 資産形成・収益改善系の資料で最頻出。目標達成ストーリーの背骨に使う

### P-7 折れ線(時系列・シナリオ比較)
- 条件: 「〜年までにこう推移する」「シナリオA/Bでこれだけ違う」
- 仕様: 実績=実線、予測・シナリオ=破線。基準シナリオはグレー、提案シナリオは緑。
  終点に値ラベル+シナリオ名を直接置く(凡例ボックスより線の終端ラベルを優先)
- 目標線は水平の緑点線+ラベル「目標: X億円」

### P-8 2×2ポジショニング
- 条件: 「〜は2軸で整理でき、狙うべきは右上」位置づけ・優先順位のメッセージ
- 仕様: 軸ラベルは両端に(低↔高)。象限に短い名前を付ける。推奨領域を薄緑で塗る。
  プロット対象は円+ラベル、円の大きさで第3変数(市場規模等)を表してよい(その場合凡例必須)

### P-9 ドライバーツリー/ロジックツリー
- 条件: 「Xはa×b×cに分解できる」「課題の構造は〜」因果・分解のメッセージ
- 仕様: 左に結果指標、右へ分解(3階層まで)。枝は直角コネクタ。定量ツリーは各ノードに
  数値+単位。施策が効くノードに緑バッジ
- 資産形成系: 純資産=(収入−支出)+資産リターン−利息−税 の分解に使う

### P-10 ロードマップ/フェーズ計画
- 条件: 「〜の順で実行する」「3年で3段階」時間軸実行のメッセージ
- 仕様: 横軸=時間(四半期/年)。フェーズを矢羽で区切り、各フェーズに名前+ゴール。
  施策は横バー、マイルストーンは菱形。現在位置に縦点線
- 各フェーズの下にKPI/体制を添えると実行資料として強くなる

### P-11 対比型(Before/After、現状/あるべき、A案/B案)
- 条件: 対象が2つで「違い・役割の別」がメッセージ。「現状はXだが、あるべきはY」
  「Aを主、Bを従とする」もこの型(二項対立に限らない)
- 仕様: 左右2カラム。緑基調=推奨・採用・主とする側、グレー基調=もう一方。
  変化を語る場合は中央に太い変化矢印、併存(主/従)の場合は矢印なしで下部に結論バンド。
  行を揃えて同じ観点を同じ高さで対比する(観点ラベルを中央か左端に)

### P-12 テーブル+評価記号(ハーベイボール/○△×)
- 条件: 選択肢の多観点評価で「どれを選ぶか」。「A案が総合的に優位」
- 仕様: 行=選択肢、列=評価軸(+重み)。記号は4段階まで(●◕◑○ か ◎○△×)。
  推奨案の列/行をGREEN_PALE(#EFF7EF)で塗り、結論を右端列「評価」にまとめる。凡例必須

### P-13 キーナンバー強調
- 条件: 1つの数字がメッセージそのもの(「市場は3年で2倍」「必要投資は7,000万円」)
- 仕様: 巨大数字(60-80pt、緑)+単位+1行の意味づけ+小さな根拠図(ミニ棒/折れ線)。
  エグゼクティブサマリーの視線アンカーや章扉に使う。多用禁止(資料に1〜3枚)

### P-14 エグゼクティブサマリー/構造化箇条書き
- 条件: 資料冒頭の全体要約、または図解に落ちない定性論点の整理
- 仕様: 左端に論点ラベル列(緑の短い見出し: 現状/課題/提言/効果)、右に各1〜3行の文。
  行間を空け、罫線は薄い水平線のみ。**ただの箇条書き1段組は禁止** — 必ず「ラベル+本文」の
  2列構造にする(読者が拾い読みできる)
- 注意: P-14は文章の壁になりやすい。本編で使う場合も1項目30字以内・数値there含みで書き、
  定量内容が3個以上あるなら図解パターンへ逃がす(density-composition.md §1.5)

### P-15 高密度インベントリ表(=R7)
- 条件: 「〜には様々なXが存在する」網羅性そのものが主張の核(リスク一覧、要件一覧、
  施策棚卸し)。行数10行以上でも削らない
- 仕様: R7準拠。左から「行グループ縦ブラケット/分類ラベル(色帯)/項目名/説明(全行に
  25〜45字)」。右端にコールアウト帯(C-2)でSo Whatを1点集約。凡例不要、Source必須
- 行が20行を超えたら「開業前/開業後」のような大分類で2枚に分割

### P-16 チップ・ポートフォリオマップ(=R8)
- 条件: 位置づけ(2軸)を語る対象が実名で10個以上あり、「どこに何があるか」の面の
  議論をしたい(技術ポートフォリオ、事業ポートフォリオ、競合マップ)
- 仕様: R8準拠。軸ラベルに定義併記(L: TRL1-4等)、チップは実名の小矩形、塗り=所属状態、
  領域枠+番号バッジで移行ストーリーを重ねる。チップ選定根拠をNote行に必ず書く
- 対象が9個以下で抽象的な位置づけ議論ならP-8のままでよい

### P-17 ポジション図+属性表の複合(=R9)
- 条件: 複数対象(基金・施策・事業等)について「全体の中での位置づけ」と
  「個別の属性詳細(目的・対象・金額・スキーム等)」の両方を1枚で見せたい
- 仕様: R9準拠。左に位置づけ図(幅約8cm)、右に属性表(残り幅)。左図の対象と
  右表の行を上下位置または接続線で対応させる。金額列は右揃え太字

### P-18 ストラクチャー図(アクター相関・マネーフロー)(=R10)
- 条件: 「誰から誰に、何が(カネ・契約・モノ・サービス)流れるか」の構造が主役。
  事業スキーム、資金調達、M&Aストラクチャー、業務委託構造、レバレッジ設計
- 仕様: R10準拠。アクター3層配置、全矢印にラベル、リスクマーカーで所在を明示、
  右にオプションリスト(番号対応)、下に結論バナー
- アクターは10個まで。超えるなら周辺アクターを「…等」に束ねる

### P-19 バリューチェーン俯瞰マップ(鳥の目)(=R11)
- 条件: テーマ全体の構造地図を定義したい(資料の第1章、または議論の土台)。
  「全体はこう構成され、各部の重みはこうだ」
- 仕様: R11準拠。大工程チェブロン+シェア%バッジ、要素ボックス縦積み、供給関係矢印、
  点線枠=域外、共通レイヤー帯。**後続スライドでの再掲オーバーレイを前提に設計する**
  (テンプレート関数化)
- 要素は1列4〜8個×4〜6列が上限。溢れる要素は「〜等」に含める

## 選択決定木(Phase 2で必ず通す)

メッセージラインの述語・論理型から機械的に選ぶ:

```
Q1. メッセージは「1つの数字」で言い切れるか?
    YES → P-13(キーナンバー) 終了
Q2. 時間軸(いつ・順番)が主役か?
    YES → 実行計画なら P-10 / 推移の事実なら P-7(または P-5)
Q3. 比較が主役か?
    YES → 対象2つ → P-11
        → 対象3+×単一指標の大小比較 → P-5
        → 対象3〜5×「基本属性+構成比」の多面定量比較 → R5型(C-5+C-1)
        → 対象3+×観点3+:
            セルが状態(あり/なし/程度)に落ちる → P-2
            セルに理由・条件の記述が要る → P-3
            選択肢を評価して1つ選ぶ → P-12
        → 位置づけ(2軸マップ)を語る → 対象が実名10個以上 → P-16 / それ以外 → P-8
Q4. 分解・因果(なぜ/何で構成)が主役か?
    YES → 定量ギャップの分解 → P-6 / 指標・課題の構造分解 → P-9
Q5. 仕組み・プロセス(どう動く/どう回す)が主役か?
    YES → 工程の流れ(時間・順序のフロー) → P-1
        → アクター間のカネ・契約・モノの流れ(相関構造) → P-18
Q6. 網羅・分類(何が必要/どんな種類)が主役か?
    YES → 行ごとに説明が要る10行超のリスト → P-15 / 分類×観点の整理 → P-4
        → 位置づけの見立て+対象ごとの属性詳細の併載 → P-17
        → テーマ全体の構造地図(バリューチェーン・産業構造) → P-19
          (同じ地図で複数論点を語るなら P-19+再掲オーバーレイ)
Q7. 論点整理(全体地図+論理+次の問い)を1枚でやりたいか?
    YES → R6型(C-3の3パネル)
Q8. どれでもない(定性論点の整理)
    → P-14。ただし本編で連続2枚まで。3枚続くなら構造化不足を疑い Phase 1 に戻る
```

パターン確定後、**必ず density-composition.md で複合構成(C-1〜C-5)の併用と
密度検算を行う**。単一パターン+複合構成なし、はエグゼクティブサマリー等を除き稀。

決定木の出力に対し、必ず次の2チェックを行う:
- **証明チェック**: 選んだ図解は、メッセージの主張を「見れば分かる」形で証明しているか。
  図を見てもメッセージに納得できないなら、図が悪いのではなくパターン選択が誤り
- **密度チェック**: その図に載る要素数(ボックス・行・列・系列)がパターンの上限内か。
  超過時は「2枚に分割」か「付録に詳細を逃がす」

## 図解共通の作法

- 矢印: 実線=主要な流れ、破線=代替・補助・フィードバック。矢印の意味は1資料で統一
- 強調: 1スライドに強調は1箇所(強調枠、アクセント塗り、太字のいずれか)。
  同一の意味を持つ項目群への同色地(オプションリスト・オーバーレイのハイライト群等)は
  1つの強調テーマ=1箇所と数える(design-system.md 使用規則4)。
  全部を強調することは何も強調しないことと同じ
- アイコン: 単色ピクトグラムのみ(緑系またはグレー)。多色イラスト・写真・影付き3D禁止
- 「等」「例」の明示: 例示リストは「〜等」で締め、網羅リストと区別する(R4の作法)
- 脚注番号: 図中の専門用語・略語には上付き番号を振り、最下部脚注で定義
  (例: 「SKU¹」と書き、脚注に「1. Stock Keeping Unit」)
