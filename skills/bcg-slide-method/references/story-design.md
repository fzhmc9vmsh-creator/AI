# ストーリーの設計 ― 狙い・順番・一貫性・重み付け(story-design.md)

工程 1(設計)で使う。message-storyline.md が「メッセージの作法」、この文書が
「何をどの順に、どの重さで見せるか」を決める。設計は `storyline.json`(templates にひな形)に書き、`scripts/check_storyline.py` で検査する。
(2026-11-10 新設。利用者の指摘: 「構成の順番、狙い、一貫性あるストーリー、資料の内容をスライドとして表現する重み付けの判断が足りない」
「資料の順番の意味が分からない」「本質的ではないゴミみたいなスライドのせいで必要な項目が抜けている」「付録とかゴミみたいなことするな。必要かどうかで判断しろ」)

## §0 設計の考え方 ― 悪い例と良い例(最初に読む)

資料が浅くなるのは、作り方ではなく設計の考え方で決まる。設計書を書く前に、5 つの場面の考え方を合わせる。

| 場面 | 悪い例(こうなりやすい) | 良い例 | 見分け方 |
|---|---|---|---|
| 狙い | 「東邦化学の分析結果を報告する」 | 「読み手が、786 円で買うか、何を見て買い増し・撤回するかを決められる。最終主張: 市場は ROE 6.0% の永続を前提にするが基準は 8.1%、理論株価 1,005 円で買い検討」 | 読後に読み手が取る行動が、動詞で書いてあるか |
| 順番 | 会社概要 → 業績 → セグメント別 → 13 条件 → 価値評価 → リスク(分析した順・項目の順) | 何で稼ぐ → 何が変わった → なぜ続く → 5 年後 → 誰が → 市場は何を見落としている → いくらで・いつ(読み手が信じるのに要る順) | 章を入れ替えても通じるなら、それは一覧である |
| 一貫性 | 理論株価がページによって違う。「億円」と「百万円」が混ざる。「保守的」と「原料高を織り込む」が両方ある | 数字は台帳から引き、分析を足したら結論・目次・判別表を同じ回に直す | タイトルだけを別のモデルに読ませて、最終主張を言い当てられるか |
| 重み | 13 条件を 1 枚ずつ(13 枚)。作った分析を全部載せる。サンキー図を小さく 2 枚並べる | 読み手の認識を変える示唆(深さ 4・5)だけを主役の 1 枚にし、13 条件は一覧 2 枚、開示の並べ替えは捨てる | 主役のページに「読む前の思い込み → 変わる認識」が書けるか |
| 主役の図 | 表と箇条書きで説明する。図はあるが、どこを見るかが無い | 示唆の切り口から図を決める(逆相関が崩れた → 2 軸の時系列に①②、価値の芯 → 1 株あたりの円のトルネード図)。見るところは 3 点まで | 図だけを 3 秒見て、タイトルの主張が言えるか |

**資料は、分析の投資仮説(一文)を証明する順に並べたものである。**一文の証明に要らないページは、正しくても載せない。

## §1 狙い ― 1 文で書けなければ作り始めない

`goal` に 3 つを書く。①読み手(誰が)、②読後の行動(何を決める・何をする)、③最終主張(数字の入った完全文)。
任意で ④判断の基準(`hurdle`: 分析の判断[買い・買い検討・監視・見送り]、即時に買う価格・分割で買う価格・最大の下振れ)を書ける。設定時は結論のページに明記する。
各章・各ページにも狙い(`aim`: 何を証明するか)を書く。**狙いが書けないページは要らない。**

## §2 順番 ― 読み手の問いの連鎖で決める

1. 最終主張を信じるために、読み手が順に抱く問いを書き出す(5〜8 個)。**問い 1 つが 1 章**になる。キーメッセージはその答えで、1 章に 1 本が基本(前提・人・行動のような「機能の章」を除く)。
2. 各章に「問い」と「答え(一文)」を書く。答えが書けない章は、分析が足りないか、章が要らない。
3. 依存関係で並べる。前の章の答えを知らないと理解できない章は後ろに置く(`depends_on`)。入れ替えても通じるなら一覧である。問いを立て直す。
4. 結論は最初に置く(Answer First)。枚数の上限は置かない(本編の目安は 15〜25 枚)。本編が 10 枚を超えるなら**意図つきの目次**を置く: 章 | 問い | この資料の答え | 決め手の数字 | ページ。**投資資料(銘柄分析)の目次は `L.agenda` で、序に 1 枚と各章の頭に 1 枚**(章の一覧・今の章の問いと答え・構成とページ。2026-11-19)。
   **判断を分ける最大の争点(価値を最も動かす示唆)は、結論のページで平易な言葉で先に言う(争点の予告)。詳しい証明は後の章で行う。**
   投資判断の資料では、価値の橋(現在値 → 今の利益が続く場合の価値 → 成長の上乗せ → 理論株価)は **5 章(判定)に置く**。橋の各段は 1〜4 章で
   証明済みの数字だけで組み、段ごとに証明したページの番号を書く(2026-11-18 改訂: 説明の前に橋を出すと、読み手は段の意味が分からない)。
5. **前提の章を分析の前に置く(2〜3 枚まで)。**対象(会社・製品・市場)を知らないまま分析を見せない。中身は「会社の一枚紹介(何者か・誰に何を売ってどう稼ぐか・規模)」「業界の地図(登場人物と、自社の位置)」「用語(意味と、この資料でなぜ要るか)」。沿革の並べ替えはしない。**読み手は、その会社も業界の略語も知らない賢い人**として設計する(2026-11-18: 「CSP ってなんだ？という至極当たり前の問いも出てくる。汎用 skill なんだから事業の理解をわかりやすく見せる必要がある」)。

順番の型(たたき台。問いは案件ごとに書き直す):
| 型 | 章の順 |
|---|---|
| 投資判断(5 工程。stock-analysis.md §3) | 結論 → 目次 → 0 会社と業界の前提 → 1 現在の構造(製品ポートフォリオ × PLC・P/L・CF・B/S・優位)→ 2 将来の構造(会社計画の確度 × 影響度・市場の脅威と機会・道筋 → 終点)→ 3 リスク(確率 × 影響度)→ 4 今の値段(株価の前提・同業)→ 5 判定と行動(PEG の照合・適正株価と価値の橋・13 条件・投資行動) |
| 提案 | 結論 → 状況 → 課題(なぜ今)→ 解決策 → 効果と費用 → 実行計画 → 依頼事項 |
| 報告 | 結論 → 事実 → 原因(2 層以上)→ 対策 → 次の確認日 |
| 計画 | 目標 → 現状との差 → レバーと効きの大きさ → 工程と日付 → KPI と見直しの線 |

投資判断の結論ページと「市場との差分と価値」の章には、**なぜ市場がその前提を置くのか**(見落としの構造: 誰も見ていない・複雑で分けて見られていない・数字に出るのが先・過去の失敗の記憶・統治への不信)と、**なぜ今か**(差が埋まる契機と期限)を必ず入れる。

## §3 一貫性 ― 縦・横・数字・言葉をつなぐ

| つなぐもの | 守ること |
|---|---|
| 縦(主張の木) | 最終主張 → キーメッセージ(3〜6 本)→ 各ページのメッセージ(`proves`)。キーメッセージごとに S か A を 1 枚以上置く |
| 横(ページの受け渡し) | 各ページに前のページとの接続語(`connector`: だから・なぜなら・では・しかし・具体的には・その結果)を書く。「また」「次に」が 4 割超なら組み直す |
| 数字 | 同じ量は全ページで同じ値・定義・丸め・単位・比較期間にそろえ、台帳から引く(手写し禁止)。値と差は検算で合う形にする(1,022 + 102 = 1,124) |
| 単位 | 金額の単位は資料全体で 1 つ(例: 百万円)。1 株あたりの円(株価・理論株価)は別の単位として使ってよい。会社目標も同単位に直して図に載せ、引用のみ原文に換算を添える |
| 言葉 | 同じものを別の名前で呼ばない(用語表を作る)。向きの違う形容(「保守的」と「原料高を織り込む」)を残さない。時期を書き分ける(どの期の話か) |
| 結論の更新 | 分析を足したら、結論・目次・判別表・タイトルを同じ回に直す |

## §3b 初見の読み手 ― 説明してから使う(2026-11-18 新設)

利用者の指摘: 「見出しも何を言ってるのか伝わらない」「専門用語が出てくるが注釈がない。何故その用語が必要かも不明」「比較対象の説明がない。
OPM って何？なんのための指標？本当にそれが比較の軸であってる？」「急に 31 年のサンキー図が出てくるが、それまでのスライドでそこに至る理由付けがされてない」
「結論部分で 3 工程で説明がなかったものをいきなり出すと意味不明」。原因は 1 つ: **作り手の頭の中にある前提を、読み手も持っていると思って書いた**。

| 守ること | 設計書に書くこと | 機械の検査 |
|---|---|---|
| ページは、前のページまでに説明したことだけで読める | `pages[].introduces`(このページで初めて説明する概念・数字の id)・`uses`(使う id)。`concepts[{id, label, type: fact|term|tool}]` | `check_storyline.py`: `uses` が同じページか前のページの `introduces` に無ければ誤り。判定の章で `type: fact` を新しく `introduces` したら誤り |
| 専門用語・略語は初出で注釈し、なぜ要るかを書く | `glossary[{term, plain, why, first_page}]` | `lint_deck.py pptx --storyline`: 資料の略語が `glossary` に無い、または初出のページより前に意味(`plain`)が出ていなければ誤り |
| 社内の記号を出さない | ― | `lint_deck.py pptx`: I1・L16-1・R2・Z2・N1・「S2·A3·B5」・α・「重みS」を誤りにする |
| 比べるときは相手と物差しを先に言う | `benchmarks[{page, metric, definition, purpose, why_axis, peers[{name, what, why_comparable}], rejected[{name, why_not}]}]` | `check_storyline.py`: 比較のページ(kind: peers か `compares: true`)に `benchmarks` が無い、項目が空なら誤り |
| 終点より先に道筋 | 将来の終点(kind: future_structure)の前に道筋(kind: path) | `check_storyline.py` |
| 見出しは平易に | テーマ = 平易な名詞句、なぜ見るか = 読み手の問いの形、タイトルの数字は 3 つまで | `lint_deck.py pptx`: タイトルの数字が 4 つ以上なら誤り |

**比較の軸の選び方**(突っ込まれても耐える選定): ①その指標は価値の芯(感応度 1 位の変数)に効くか、②比較対象は指標を動かす仕組み(費用構造・顧客・
成長段階)が同じか、③他の候補(会社・指標)をなぜ外したか、を `benchmarks` に書く。資料には ①の一文と、比較対象ごとの「何の会社か・なぜ比べるか」の 1 行だけを出す。

## §4 重み付け ― 何を大きく、何を小さく、何を捨てるか

中身ごとに 3 つを問うて重みを決める: **①判断を変えるか、②読み手にとって新しいか(開示のままなら低い。復元・逆算・換算した量なら高い)、③証拠は強いか。**

| 重み | 条件 | 表現 |
|---|---|---|
| S | 判断を変え、新しく、証拠が強い(主役。15〜30% は目安で超えても誤りではない) | 1 枚まるごと。タイトルに決め手の数字。配置は「1 枚の中の設計」 |
| A | 判断を支える | 1 枚。図か表が主役、右か下に読み |
| B | 知っておくべき背景・補強 | 他のページの一区画(3 分の 1 まで)か、表の数行 |
| C | 確認用 | 脚注・表の 1 行・出所 |
| D | 判断に効かない(どのキーメッセージも証明しない) | 載せない(付録に逃がさず、`dropped` に理由を残す) |

**重み S の条件を、読み手の認識で確かめる。**S のページごとに 2 つを書く(`reader_belief`・`shift`):
- 読み手は、このページを読む前に何と思っているか(通説・会社の説明・株価の前提)。
- このページを読むと、その認識がどう変わるか(数字で)。
2 つが書けないページは、正しくても主役ではない(A に下げる)。「知っていることの確認」に 1 枚まるごとを使わない。
例: 思い込み「割安に放置された成長株で、電子材料の増設が実れば株価は上がる」→ 転換「差 219 円の約 9 割は、今の利益が続くだけで埋まる。成長の上乗せは約 26 円。問うべきは利益の持続性」。
例: 思い込み「成長の主役は電子材料の増設」→ 転換「ありうる振れ幅で比べると、粗利率 2.58pt で約 ±545 円、電材は増設の全量 90t でも約 ±235 円。見るべきは粗利率」。

**投資資料では、重みを分析の示唆から決める(勝手に決めない)。**meigara-bunseki-method の `hypotheses.json` の示唆のカードを読み、
- 深さ 4・5 の示唆、価値の芯の示唆 → **必ず S**(原則 1 示唆 1 枚。`pages[].insight` に示唆の id。数が多いとき[7 個以上]は、価値への効きが小さいものを 1 枚に 2 つまとめてよい)。
- 深さ 3 の示唆 → A(S の前に置いて、S の主張の土台にする)。深さ 2 → B か、A のページの一区画。
- 示唆に結び付かない中身(開示の並べ替え)→ C 以下。S にしない。
- 弱気の反論と判定(`rebuttals`)は 1 枚、投資仮説の撤回の線(`thesis.kill`)は判別表のページに必ず入れる。
- 結論のページは `thesis` をそのまま使う: 一文、差分の表(市場の前提 | 自分の見立て)、見落としの構造と「なぜ今か」(§2)、価値の芯、判断の基準(§1 の `hurdle`)。
`python3 scripts/check_storyline.py storyline.json --analysis <分析の作業フォルダ>` が、この対応を検査する。

**切り口から主役の図を決める**(示唆の `lens` を見て、下の表の図を主役にする。迷って表や箇条書きにしない)。
| 示唆の切り口(lens・レンズ) | 主役の図 | 図に必ず入れるもの |
|---|---|---|
| 分解(L01・L12) | ウォーターフォール(増減の橋。部品 `L.waterfall`) | 最大の項目を 1 色で強調、会社の分析か自分の計算かの明記 |
| 粒度・製品群の地図 | 2 分割の表(数量で伸びた / 値上げで補った)か、品目のマトリクス | 戦略テーマの印、全品目(抜かない) |
| 加速度(L02) | 四半期・半期の棒に前年同期との差のラベル | 底と連続の期数 ①② |
| 自然実験(L04) | 2 軸の時系列(棒 = 自社の率、線 = 外部の市況。部品 `L.regimeSeries`) | ①前回のショック ②今回、相関係数 |
| 会社予想の逆算(L05) | 判別表(前提ごとの通期の着地) + 半期の推移 | 会社予想の前提の行、続行の線・見直しの線 |
| 年換算と計画(L06) | 計画の幅の帯に、年換算の棒を重ねた横棒 | 進捗 %、先行と遅れの色分け(2 色まで) |
| デュポン・ROE の経路(L07) | 3 要素の推移の表 + 「レバレッジ固定なら」の反実仮想 | 削られる pt |
| 資本の使い道(L08) | 利回りの横棒 + 資本コストの縦線 | 線を超える使い道だけ強調 |
| 逆算・織り込み(L09) | 市場の前提 | 自分の見立て の 2 列の差分の表 + 織り込み ROE と自分の ROE の棒 | 差が埋まる日付 |
| 同業の線(L10) | 散布図 + 回帰線 | 今の位置と、将来の ROE での線上の位置の矢印、決定係数 |
| 能力と市場(L11) | 能力の段差の棒 + 市場の伸びの線 | 必要なシェアの前提 |
| 換算・感応度(L16) | トルネード図(1 株あたりの円) | 変数ごとの「ありうる振れ幅」で並べる(単位あたりで比べない)。1 位を強調し、振れ幅の根拠を図の中に書く |
| 価値の橋(L18) | ウォーターフォール(現在値 → 今の利益が続く場合の価値 → 成長と変化の上乗せ → 理論株価。部品 `L.waterfall` に `axisMin`。手本 `scripts/examples/charts/c01_value_bridge.js`) | 差の何割がどの段か。株価が前提にする持続的な EPS と今の実力。段ごとに、証明するページの番号 |
| 時間・制約の解放 | ロードマップ(日付) | 判別の日、段差の大きさ |
| 人 | 経歴 → 担当 → 担う変革の表 + 年表 | 承継の確認日 |
| 逆の立場(反論) | 反論 | 検証したデータ | 判定 | 評価への反映 の表 | 判定の色は 3 種まで、評価が変わった行を強調 |
| 非対称(上振れと下振れ) | 現在の株価を 0 の線にした横棒(部品 `L.payoffBar`。手本 c02) | 左に弱気の下値幅と下値の支え、右に基準・強気の上値幅と確率 |
| 体制の転換 | 時系列に転換点の縦の破線と背景の帯(部品 `L.regimeSeries`。手本 c04) | 前後の平均線 |
| 段差と閾値 | 階段の図(部品 `L.stepChart`。手本 c03) | 損益分岐点などの閾値の横線と日付 |

- **等しく配らない。**評価の枠組み(13 条件など)や製品群を機械的に 1 枚ずつ並べない(章の軸にせず、一覧は 1〜2 枚)。枚数は重みに比例させる。
- 1 章が全体の 45% を超えたら分ける。分析の章で S が 1 枚も無い章は他の章に吸収する(前提・人・行動のような「機能の章」は S が無くても 2〜3 枚以内で置いてよい)。
- 表現の選び方: 量の比較・推移・構成 → 比例描画の図 / 多属性の対比 → 表 / 因果・仕組み → 関係図 / 時間と日付 → ロードマップ / 判断の線 → 判別表(条件 | 続行 | 見直し)。1 ページ 1 主役とし小さい図を 2 枚並べない(例外は上の S 7 個以上のとき)。

**1 枚の中の設計**
- **視線の順と面積**: 主張のタイトル → 主役の図(本文の 6 割)→ 読み(So What、2〜2.5 割・3 行以内)→ 根拠の数字と出所(1.5〜2 割)。
- **タイトル**: 最上部に主語・動詞・決め手の数字を含む 1〜2 行の主張文を置き、`pages[].message` と一致させる。「〜の分析」「〜の推移」のような見出し語にしない。
- **図題と凡例**: 図の真上に「何と何を比べた図か + 単位」を 1 行で置く。凡例の枠を使わず、線や棒の端に系列名を直接書く。
- **①②③ と「見るところ」**(部品 `L.marks`・`L.lookBox`): ①②③ は図の変化点に置いて横に短い解釈と数字を添え、横の「見るところ」の箱にも同じ番号で 1〜2 行(最大 3 点)書く。
- **数字と表**: 有効数字 3 桁を目安とし、率は小数 1 桁、差は pt と書いて % と区別する。表は右揃えにする。
- **色の意味**: 資料全体で固定する(灰色 = 過去・比較、濃い 1 色 = 注目、赤 = 下振れ)。

## §5 設計書 `storyline.json`

```
deck_type(stock | general) / goal{reader, decision, claim, hurdle(任意)} / unit / horizon{year, why}(投資資料) / key_messages[{id, text}] /
chapters[{no, name, stage(投資資料: intro|current|future|risk|valuation|verdict), question, answer, depends_on[]}] /
pages[{id, chapter, role(cover|summary|agenda|glossary|body), kind(投資資料のページの種類。stock-analysis.md §3), message, aim, proves[], weight, form, hero,
       key_number, connector, introduces[], uses[], compares, insight(分析の示唆の id), reader_belief・shift(重み S のとき必須)}] /
concepts[{id, label, type}] / glossary[{term, plain, why, first_page}] / benchmarks[{page, metric, definition, purpose, why_axis, peers[], rejected[]}] /
dropped[{what, why}]
```
検査: `python3 scripts/check_storyline.py storyline.json`(投資資料は `--analysis <分析の作業フォルダ>` を付ける)。PASS してから実装する。設計書は納品物に添える。
利用者が確認の場を求めたとき以外は、承認待ちで止まらず完成品まで作る(設計は自分で通し読みと検査で固める)。

## §6 仕上げの確認(工程 3 で)

1. タイトル(`pages[].message`)だけを通し読みして最終主張に着くか確かめる。タイトル一覧だけを別モデル(Gemini の Hydrogen など)に渡し、「最終主張・判断・決め手の数字 3 つ・いちばん意外な点」を答えさせる。`goal.claim` と合わなければ組み直し、「いちばん意外な点」が S の `shift` と合わなければ主役が立っていない。
2. 結論ページの主張・数字・判断の基準(`hurdle`)、目次の「答え」、判別表が本編の最新分析と合っているか照合する。
3. S のページで、主役の図が読める大きさ(文字 8pt 相当以上)かつ §4「1 枚の中の設計」を満たしているか確かめる。
4. 全ページの文字を抜き出して機械で照合し、単位の混在(「億円」など)・古い数字・同じ量の食い違い・検算のずれを探す。別モデルに全文を渡し、用語の不統一・向きの違う形容の混在・時期の取り違え・論理の矛盾を査読させる。
5. `dropped` に捨てたものと理由が書いてあり、付録に逃がしたページが無いことを確かめる。
