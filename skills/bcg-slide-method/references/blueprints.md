# ブループリント集(shape単位の設計図 — 忠実再現の実体)

**このファイルの使い方が本スキルの生命線。** レイアウトを発明するな、写経しろ。

- 各ブループリントは実在BCGスライドをshape単位で採寸した設計図。実装者は
  **座標・寸法・色・フォントを表のとおりに写経**し、コンテンツスロット(《》表記)に
  中身を流し込むだけ。座標の「調整」「アレンジ」は禁止(可変と明記した箇所のみ可変)
- 単位はcm(python-pptx: `Cm()`)。色・フォント定数は design-system.md のパレット名
- 全shapeは「先に寸法→文字数検算→入らなければ**文字を削る**」。座標を動かして
  収めることを禁止する(これが表示崩れの根源)
- スロットの(≤n字)は全角換算の上限。超過コンテンツは設計書の段階で要約し直す

## 手組みチャート部品(全ブループリント共通)

design-system.md §7の幾何式に従う。**必ずデータ辞書→座標計算→描画の順**で実装し、
計算をコードに残す。ラベル全打ち・軸ゼロ始まり・同型バーの同寸を厳守。

## 写経ルール(実装時の禁止事項)

1. 表にない座標・寸法・色・サイズを使わない(可変と明記した箇所のみ計算式で決める)
2. スロット上限を超える文字は**書く前に**削る。auto_size・自動縮小に頼らない
3. shapeの追加は「行・列・チップの繰り返し」のみ。新種の装飾を足さない
4. 実装順: 共通フレーム→背景帯→表・フィールド→バー・チップ→矢印→バッジ→ラベル
5. 完成後は必ず audit-loop.md の機械監査スクリプトを実行し、PASSログを取得する

## テキストボックスの高さ・積み上げの絶対規則(崩れの根絶)

実際の失敗解剖より: 「高さ1.03cm固定のボックス」を行ピッチ0.60cmで積んだ結果、
重なり204ペア・溢れ186件が機械的に発生した。以下を全shapeに適用する:

1. **高さの適用区分**: ブループリント表に固定hが明記されたグリッド要素(列ヘッダ・
   ファクト行・チップ等)はその値を使い、**文字数検算で入ることを確認**(入らなければ
   文字を削る)。h可変・内容主導のスロット(箇条書き・示唆・説明・脚注)は必ず計算式:
   `h = ceil(字数 / floor((w−0.4)/(pt×0.0353))) × pt×0.0353×1.25 + 0.2` (cm)。
   **どちらでもない「なんとなくのデフォルト高さ(例: 1.03cm)」は禁止**
2. 改行位置は読点・区切りで手動指定し、行頭に「、」「。」が来る自動折返しを避ける
3. **縦に積むテキストのピッチ ≥ 上のボックスの計算高さ + 0.1cm**。
   ピッチ < ボックス高さ の積み上げは定義上必ず重なる(最頻の崩れ)
4. **「ラベル+値」「項目の列挙」は複数ボックスを重ねて表現しない**:
   1つのテキストフレーム内の複数段落(改行)にするか、行ピッチを計算して並べる
5. 複数行になるスロット(箇条書き・説明)は、行数×行高で先に総高さを見積もり、
   ゾーンに入らないなら**文字を削る**(ボックスを重ねて誤魔化さない)
6. バーの高さ・幅が0.15cm未満に潰れる小さい値は、バーは最小0.1cmで描き
   値ラベルをバーの外(上/右)に置く(潰れて見えない棒を放置しない)。
   セグメント内に入らない小さな%ラベルは右外に引出しで置く
