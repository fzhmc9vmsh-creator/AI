# メッセージ抽出とストーリーライン設計

文章(レポート)からスライドの骨格を作る手順。**図解の巧拙より前に、ここでの
論理設計が品質の7割を決める。**

## 1. メッセージ抽出

入力文章を読み、以下を抽出して一覧化する:

1. **最終主張(Governing Thought)**: この資料全体が読者に取らせたい行動・判断は何か。1文
2. **キーメッセージ(3〜5個)**: 最終主張を支える柱。各1文
3. **根拠・データ**: 各キーメッセージを支える事実・数値・事例。**出所とセットで**記録
4. **反論と再反論**: 読者が抱く「本当か?」への備え(リスク・限界・代替案の棄却理由)

抽出時の規律:
- 文章に書いていない主張を創作しない。根拠の薄い主張は「未成熟な論点」として区分
- 数値は原文の値・単位・期間をそのまま転記(丸めは表現段階で行い、抽出段階では行わない)
- 出所が段落末に一括で書かれている場合は、数値ごとに出所を割り付け直す。割付が
  確定できない数値には【出所要確認】タグを付け、工程0の不足確認の質問で解消する（設計段階でユーザー確認待ちにしない）
- 依頼事項(読者に取ってほしいアクション)が原文にない場合、既存の主張から論理的に
  構成してよいが、設計書に【要ユーザー確認: 依頼事項は本分析からの構成】と明示する

## 2. ピラミッド構造への整理

```
        最終主張(1)
       /     |     \
   キーMsg1  キーMsg2  キーMsg3     ← 横: MECE(モレなくダブりなく)
   /  |  \    ...
 根拠 根拠 根拠                    ← 縦: So What?(下から上が導ける)/ Why So?(上から下に理由がある)
```

検証テスト(全て通るまで直す):
- **縦テスト**: 各キーメッセージに「So What?」→最終主張が返るか。根拠に「Why So?」→答えがあるか
- **横テスト**: キーメッセージ同士に重複・欠落がないか。並び順に必然性があるか
- **読者テスト**: 読者が既に知っていることの再説明に柱を使っていないか

## 3. ストーリーライン(スライドの並び)

> 章の順番・各ページの狙い・一貫性・重み付けの決め方は `story-design.md` が正。下の標準型はたたき台であり、
> 章は読み手の問いの連鎖で並べる。「付録へ逃がす」は使わず、1 枚ずつ必要かどうかで判断する(要らないものは捨てる)。

### 標準型(意思決定を取りに行く資料)

```
1. 表紙
2. エグゼクティブサマリー(最終主張+キーメッセージ全部を1枚で)
3. 目次/本編の構え
4〜. 本編: キーメッセージごとに 現状認識 → 分析 → 打ち手 → 効果
n-1. 実行計画(ロードマップ・体制・KPI)
n. 依頼事項(読者に取ってほしいアクション)
```

- **結論先出し(Answer First)が原則**。経営層向けは必ずサマリーを2枚目に置く
- 検討素材(議論用)の場合のみ、論点→選択肢→評価の順で開いてよい
- 1つのキーメッセージに使う枚数は1〜4枚。枚数は重み(story-design.md §4)に比例させ、5枚を超えるなら重みを見直して絞る

### 章構造のナビゲーション

本編10枚超かつ3章以上なら右上に「現在地」を示す(章ラベル文字、またはナビゲーションサムネ。仕様は design-system.md)。
10枚以下の単線構成ではナビは不要。読者を資料内で迷子にさせない。

## 4. スライド分割の規則

- 「本編」とは、エグゼクティブサマリーから依頼事項までの主張を持つ全スライドを指す
  (表紙・目次は本編外)
- **1スライド=1メッセージ**。1枚に2つの主張が載ったら分割する
- 逆に、1メッセージを2枚に割らない(割りたくなったらメッセージが2つ隠れている)
- **深掘りスライドは許可**: あるキーメッセージの中の最大ドライバー等を1枚使って
  掘り下げてよい(ピラミッド上は親の子として扱い、MECEの横並びには数えない)。
  その場合、リード文に深掘りの理由を明示する(例: 「ギャップの約半分を占める
  最大ドライバーのため詳述」)。読者を粒度変化で迷わせない
- メッセージのないスライド(データだけ貼った枚)は本編に置かない。不要な枚は捨てる
- **メッセージラインの通し読みテスト**: 全スライドのメッセージラインだけを縦に並べて
  音読し、それだけで論旨が通ることを確認してから作図に進む

## 5. メッセージラインの作法

メッセージライン=スライド最上部の緑色の文。基準スライドR1〜R11はすべてこの作法:

1. **主張を含む完全な文**にする(「〜している」「〜が必要」「〜すべき」)。
   体言止め(「市場環境について」)は禁止 — それはメッセージではなくラベル
2. **最大2行・2行合計で全角70字以内**(メッセージ幅26.5cm・18ptの1行は約39字が上限。
   design-system.md §4の式で検算)。3行になるなら主張を絞れていない
3. 可能な限り**数値・固有名詞で具体化**する
   - 弱: 「コスト削減の余地がある」
   - 強: 「物流費は輸送モード最適化で年▲12%(▲3.2億円)削減できる」
4. 対比・逆接で緊張感を作れる場合は使う(R2:「国により実施している施策は異なる**が**、
   前述の4カテゴリで複合的に支援を行っている」)
5. リード文(メッセージ直下の黒い小さめの文)は「何の話か」の限定に使う
   (R1: 「製造業E社におけるフレキシブルなサプライチェーン全体オペレーション構築」)。
   主張はメッセージに、スコープ定義はリードに、と役割を分ける

## 6. 数字の見せ方 10則

分析スライドの信頼性は数字の扱いで決まる。

1. **単位と期間を必ず明記**(億円/年、%pt、2025年度)。軸ラベル・凡例・脚注のどこかに必ず置く
2. **絶対値か割合かはメッセージで選ぶ**: 規模を語るなら絶対値、構成・効率を語るなら割合、
   両方要るなら絶対値の図+割合の注記
3. **比較には基準を置く**: 前年比、計画比、業界平均比。裸の数字を並べない
4. **桁を丸める**: 本編は有効数字2〜3桁(3.24億円→3.2億円)。精密値は脚注へ
5. **軸をゼロから始める**(棒グラフ)。差を誇張したい誘惑で軸を切らない。
   折れ線で変化率を見せる場合のみ切ってよい(切ったことを軸に明示)
6. **スケールをまたぐ数字を同じ図に入れない**(売上1,000億と利益率3%は別の図か2軸を明示)
7. **出所と時点を書く**(Source: 有価証券報告書2025年3月期、Expert interviews、BCG分析の類)。
   自分の推計は「XX推計」と明記して事実と区別する
8. **端数の不整合を潰す**: 構成比の合計が100%になるか、内訳の和が合計と一致するかを検算
9. **1図のデータ系列は5本まで**(100%積み上げの構成セグメントは7つまで)。
   超える分は「その他」に束ねるか図を分ける
10. **数字の意味づけを添える**: 「4,860億円(前年比+21.5%)」のように、読者が評価に使う
    参照点をカッコで併記する

## 7. スライド設計書フォーマット(Phase 2の成果物)

スライド1枚につき以下を記述する:

```markdown
### Slide N: [仮タイトル]
- メッセージライン: (1文そのまま)
- リード文: (あれば)
- 表現パターン: [P-x 型名 または R-y型](基準: R-n / R対応なし・P-x準拠。理由: …。
  再掲時は「P-19+再掲オーバーレイ(ベース: Slide N)」)
- 複合構成: C-_(なしの場合は、なしでメッセージが証明しきれる理由)
- ボディ要素:
  - (要素1: 例: 3段階チェブロン「作る/運ぶ/売る」)
  - (要素2: …)
- データと出所: (数値: 出所, 時点)
- 密度検算: 想定文字量__字 / 情報単位__個 / 数値__個 / 階層__層
  (density-composition.md §6。薄すぎ警報該当なら実装に進まない)
- 脚注/凡例: (あれば)
- レイアウト割付: (design-system.md のゾーンへの配置。特殊があれば座標)
```

全スライドの設計書を並べたら、メッセージラインの通し読みテストを再実行し、
利用者が確認の場を求めたときだけ承認を得て、それ以外は検査PASSをもって実装へ進む。
